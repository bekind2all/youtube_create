# 일러스트·아이콘·장면 구성과 전환

## 사용자 피드백과 목표

2026-09-27: 사용자는 현재 영상의 동일한 패턴과 정적인 화면 전환을 지루하게 느꼈다. 내용에 맞는 일러스트·아이콘·픽토그램과 감각적인 텍스트·박스 구성, 다양한 모션을 원한다.

현재 Aside 본편은 **HyperFrames**로 제작되었다. 기존 구현의 공통 `y:14 → 0` 등장, 비슷한 종이·박스 구성, 캡처의 느린 확대를 전체 연출 규칙으로 답습하지 않는다. Remotion으로 바꾸는 것 자체가 해결책은 아니다. 기존 엔진에서 구도·시각 소재·의미 있는 움직임을 설계한다.

목표는 **오늘AI의 일관된 색과 선 안에서, 화면마다 다른 방식으로 이해시키는 것**이다. 아래 패턴은 선택지이며, 모든 영상에 전부 넣거나 정해진 순서대로 순환시키지 않는다.

## 스타일별 연출

사용자가 유지하기로 한 두 스타일은 **1 · 화면 중심**, **2 · 일러스트 중심**이다. 스타일 번호는 팔레트 번호와 별개이며 롱폼·숏폼 모두에 적용한다.

- **스타일 1:** 큰 타이포와 실제 캡처가 중심이다. 결과 확대, 입력·출력 비교, 구절 등장, 정확한 밑줄·화살표, 의미 있는 박스 전환을 사용한다. 작은 아이콘은 보조 요소다. 큰 설명 일러스트는 필수 조건이 아니다. 이전 바이브코딩 V2를 구도 참고로 삼되 같은 제목·카드 틀을 반복하지 않는다.
- **스타일 2:** 큰 상황·과정 일러스트가 설명을 맡는다. 입력이 일정으로 바뀌거나 돋보기·연필로 확인·수정하는 부분 동작을 설계한다. 실제 결과를 증명하는 장면에는 캡처를 유지한다. 바이브코딩 V3를 참고하되 매 장면을 그림으로 채우지 않는다.
- 두 스타일의 폰트·선·선택 팔레트·자막·음성·팩트체크 기준은 같다. 일러스트와 실제 제품 UI의 구분도 유지한다. 스타일 선택은 이 엔진을 바꾸거나 음성을 다시 만드는 이유가 아니다.

## 필요한 시각 표현을 선택한다

| 표현 | 역할 | 오늘AI의 처리 |
| --- | --- | --- |
| 설명 일러스트 | 여러 정보가 어떻게 정리되고 바뀌는지 설명 | 선택한 팔레트의 진한 선·밝은 면·강조색. 의미 있는 부분을 순서대로 그리고 이동·결합 |
| 아이콘·픽토그램 | 메일·검색·일정·자료·선택 같은 행동을 빠르게 식별 | 한 가지 벡터 선 스타일과 비례를 유지. 짧은 라벨이나 실제 결과와 연결 |
| 실제 제품 화면·실사 | 출처와 실제 사용 맥락을 보여줌 | 원래 화면 유지, 필요한 영역 확대, 스케치 주석으로 시선 유도 |

- 아이콘은 작은 장식, 픽토그램은 간결한 행동·상황, 일러스트는 설명할 관계가 필요한 곳에 쓴다. 명칭보다 전달할 내용으로 선택한다.
- 선 굵기·둥근 끝·코너·디테일 정도를 통일한다. 얇은 선 아이콘, 광택 3D 이모지, 귀여운 클립아트를 한 화면에 섞지 않는다.
- 비교표를 설명할 때 “표” 아이콘 하나만 크게 보여주는 것으로 결과 화면을 대신하지 않는다. 아이콘은 도입이나 연결을 돕고 실제 값이 있는 결과로 이어진다.
- 같은 뜻에는 같은 픽토그램을 재사용한다. 순전히 다양하게 보이려고 메일 아이콘의 스타일을 매번 바꾸지 않는다.
- 기존 라이선스가 확인된 SVG 자산을 우선하고, 없으면 주제에 필요한 단순 벡터나 설명용 일러스트를 제작한다. 출처가 불분명한 이미지 검색 결과를 그대로 베끼지 않는다.
- SVG는 움직일 부분을 레이어·그룹으로 구분한다. 새 래스터 일러스트는 요소를 별도로 다룰 수 있게 만들고, 움직임을 위해 그림 전체를 흔드는 것으로 끝내지 않는다.
- 실제 제품 UI처럼 보이는 일러스트에는 예시 표시를 넣는다. 정확한 공식 UI가 필요한 장면은 캡처를 사용한다.

### 그림이 실제로 보일 만큼 크게 만든다

아래는 **스타일 2 또는 큰 일러스트를 쓰기로 한 장면**의 기준이다. 스타일 1의 실제 캡처를 큰 그림으로 교체하는 공통 명령이 아니다.

- 작은 선 아이콘을 제목 옆에 붙여 둔 채 중앙에 텍스트 박스만 남으면 개선이 아니다. 손에 든 휴대폰, 문서를 읽는 돋보기, 촬영 카메라와 알림 시계처럼 상황 전체를 보여준다.
- 설명 장면의 주 일러스트는 자막을 제외한 주요 시각 영역의 약 절반부터 구도를 검토할 수 있다. 고정 면적 할당이 아니라 휴대폰 크기에서 확대 없이 알아보이는지가 기준이다. 화면 캡처·수치가 주인공인 장면에는 그림을 억지로 채우지 않는다.
- 큰 면과 충분히 굵은 외곽선을 함께 사용한다. 얇은 선만 복잡하게 늘려 축소했을 때 사라지지 않게 한다.
- “음성 → 정리된 일정”, “요청 → 코드 → 앱”, “결과 확인 → 필요한 부분 수정”처럼 그림이 설명의 일부를 담당한다. 들어온 뒤 통째로 떠다니게 하지 말고 부분의 상태를 바꾼다.

### 함께 제공하는 레이어 일러스트

`assets/illustrations/`의 SVG는 이 프로젝트에서 직접 제작한 설명용 그림이다. 실제 제품 UI나 검증된 실행 화면이 아니다.

| 파일 | 설명과 움직일 부분 |
| --- | --- |
| `voice-to-calendar.svg` | 휴대폰·손 → 음성 파형 → 시간 → 일정. `phone`, `hand`, `wave`, `date-token`, `calendar`, `event`, `connector` |
| `ai-workbench.svg` | 요청 종이 → 노트북 코드 → 앱. `request`, `laptop`, `code`, `app`, `cursor`, `connector` |
| `review-and-revise.svg` | 결과를 확대해서 확인하고 수정. `app`, `magnifier`, `pencil`, `edit`, `reminder` |
| `filming-reminder.svg` | 촬영 전 알림 설정. `camera`, `clock`, `bell`, `ring`, `time` |

- SVG를 인라인해 호스트 안의 `[data-part]` 그룹을 선택한다. 선 드로잉 경로는 `[data-draw]`다. 전역 ID에 의존하지 않는다. 래스터 이미지로만 넣으면 부분 애니메이션을 할 수 없다.
- 색 변수 `--art-ink`, `--art-paper`, `--art-accent`, `--art-on-accent`, `--art-deep`, `--art-soft`를 현재 선택 팔레트의 HEX에 연결한다. 기본 fallback은 팔레트 02다. `--art-on-accent`는 강조 면 위의 글자·선으로, 02의 옐로 면에는 남색, 01의 빨간 면에는 아이보리를 쓴다. 그림 안 숫자·문구·시계 바늘도 새 사례의 실제 값에 맞춰 함께 수정한다.
- 같은 시간에 같은 모습으로 그려지는 타임라인을 만든다. 그림 도착 → 대상 변화 → 읽기 구간을 구분한다. 이 네 장면을 모든 주제에 같은 순서로 복제하지 않는다. 다른 업무에는 같은 색·선 문법으로 필요한 그림을 만든다.

## 내용에 맞는 장면 구성 선택

| 장면 목적 | 화면 구성 | 설명하는 움직임 |
| --- | --- | --- |
| 핵심 결과·후크 | 결과를 크게, 짧은 핵심 문구를 비대칭으로 배치 | 결과의 핵심 영역이 먼저 드러나고 문구가 빠르게 정착 |
| 전후 차이 | 같은 대상의 이전/이후, 대비되는 크기와 위치 | 흩어진 탭이 모여 정리된 표로 연결. 이동하는 공통 요소로 관계 표현 |
| 작업 과정 | 글 목록보다 실제 입력·작업물·연결선 | 요청 문장 → 자료에서 추출 → 결과 완성 순서로 이동·드로잉 |
| 제품 기능 설명 | 실제 화면 중심, 필요한 부분의 확대 뷰 | 해당 영역으로 시선을 이동시킨 후 호출선·주석 표시 |
| 일정·메일·생활 예 | 달력·메일 등 상황을 이해할 수 있는 일러스트 | 메일의 날짜가 일정으로 옮겨지는 과정을 보여줌. 가상 내용은 예시 표시 |
| 숫자·요금·조건 비교 | 중요한 차이가 크게 보이는 타이포와 비교축 | 두 값이 같은 축에 놓이고 차이만 강조. 숫자는 확인된 값으로 유지 |
| 주의·사용자 확인 | 한 문장과 하나의 행동 대상 | 전송 직전 초안이 사용자가 검토할 위치로 이동하고 정착 |
| 정리 | 앞서 본 결과를 다시 연결 | 이전의 핵심 작업물이 작게 모여 하나의 활용 흐름을 만듦 |

- 장면의 정보량과 목적이 바뀔 때 구도도 바꾼다. 대형 타이포, 전체 화면 데모, 비대칭 일러스트, 비교 구도를 적절히 섞는다.
- 모든 화면에 상단 제목·하단 자막·가운데 같은 큰 박스를 고정하지 않는다. 자막 안전 영역은 유지하되 제목·주인공 시각 요소의 크기와 위치를 설계한다.
- 새로운 단락에서 구도를 바꾸더라도 같은 배경·선·서체·강조색이 브랜드를 이어준다. 변화를 주기 위해 승인된 HEX를 바꾸지 않는다.
- 연속 장면이 같은 구도·등장·퇴장 방식이면 반복이 필요한 비교인지 판단한다. 이유가 없으면 주 소재나 공간 구성을 바꾼다. 무조건 N초마다 전환하는 규칙을 만들지 않는다.

## 텍스트와 박스를 다루는 방법

**텍스트**

- 핵심 단어와 설명의 크기 차이를 분명히 하고, 넉넉한 여백·정렬선으로 시선을 유도한다. 모든 문장을 비슷한 크기·굵기로 채우지 않는다.
- 제목은 마스크 안에서 한 구절씩 드러내기, 줄별 짧은 시차, 핵심 단어만 교체하기 등 내용에 맞는 방식을 택한다.
- 첫 3초의 결론은 읽을 수 있게 빨리 완성한다. 글자 하나씩 오래 쓰는 효과는 짧은 주석이나 보조 장면에 한정한다.
- 자막은 별도 읽기 영역이다. 제목의 모션을 자막에 그대로 복제하거나 각 음절을 튕기게 하지 않는다.
- 강조 효과는 글자가 읽을 수 있는 상태가 된 뒤 시작한다. 제목 자체가 움직이는 중에 화살표가 다른 위치를 가리키지 않도록 한다.

**박스·면**

- 박스는 실제 문서, 비교 영역, 그룹 등 정보의 경계를 나타낼 때 쓴다. 모든 문장과 아이콘에 같은 둥근 카드를 씌우지 않는다.
- 경계 없이 놓인 큰 글자, 선으로만 구분한 비교, 겹친 실제 작업물, 넓은 색면을 함께 활용한다. 여러 스타일의 장식을 한 장면에 몰아넣지 않는다.
- 박스 외곽이 그려진 뒤 내용이 채워지거나, 기존 면이 확장되어 다음 화면의 기반이 되는 동작을 사용할 수 있다.
- 코너·선·그림자는 작은 토큰 집합으로 통일한다. 정보 위계는 주로 크기·위치·여백으로 만들고, 모든 항목에 그림자를 추가하지 않는다.

## 모션은 등장 이후에도 설명을 진행한다

장면마다 아래 세 시점을 정한다. 각 시점에 새 움직임이 반드시 필요한 것은 아니다.

1. **발견:** 시청자가 무엇을 먼저 볼지 정하고 보여준다.
2. **변화:** 그 정보가 어떻게 정리·비교·전달되는지 움직임으로 설명한다.
3. **이해:** 완성된 결과를 읽을 수 있도록 안정된 상태를 유지한다.

예를 들어 메일 세 장이 나타나고 끝나는 대신, 설명할 날짜와 준비물이 순서대로 강조되고 일정표의 대응 항목으로 이어지게 한다. 자료 종류가 설명용 예시라면 그 표시는 계속 유지한다.

- 주 시선은 한 번에 하나의 동작을 따라갈 수 있게 한다. 배경·본문·캐릭터·주석이 모두 동시에 움직이지 않는다.
- 짧은 등장에는 약 0.25~0.5초, 대상 이동·연결에는 약 0.45~0.9초를 초안값으로 삼을 수 있다. 음성·이동 거리·읽기 시간을 기준으로 조정한다.
- 방향, 이동량, 감속을 기능에 맞게 고른다. 차분한 정보 영상에 과한 탄성·반복 바운스·무의미한 회전을 기본값으로 쓰지 않는다.
- 정적인 설명 구간을 줄이되 **승인된 롱폼 쉼과 결과 읽기 구간은 지킨다.** 모든 정지를 없애는 것이 목표가 아니다.

## 장면을 연결하는 방법

| 연결 방식 | 쓰기 좋은 관계 |
| --- | --- |
| 공통 대상의 위치·크기 이어가기 | 앞 장면의 문서·아이콘·결과가 다음 설명의 주인공이 될 때 |
| 결과의 한 부분을 확대해 들어가기 | 전체 비교표에서 중요한 행을 자세히 설명할 때 |
| 면·선을 이어서 다음 화면 드러내기 | 다음 단계로 넘어가며 정보 구조가 확장될 때 |
| 같은 위치에서 대상 교체 | 입력과 결과, 이전과 이후를 명확히 대비할 때 |
| 간결한 컷 | 이미 관계가 명확하거나, 시점을 빠르게 바꿀 때 |
| 부드러운 겹침 | 의미상 시간이 흐르거나 서로 다른 자료를 차분하게 연결할 때 |

- 매번 페이드로 지우고 새 카드들을 나타내는 패턴을 기본으로 삼지 않는다.
- 앞 장면의 중요한 대상을 다음 장면에서도 알아볼 수 있게 유지한다. 동작 방향과 시선의 도착 위치를 연결한다.
- 화면을 잇는 것과 사실을 주장하는 것을 구분한다. 설명용 전환이 실제 제품이 수행한 변환이라는 오해를 만들면 예시 표시나 설명을 더한다.
- 글리치, 회전, 휩팬, 광학 효과 등을 단지 화려하다는 이유로 넣지 않는다. 설명 콘텐츠의 신뢰감과 읽기 쉬움을 우선한다.

## 컴포넌트로 구현할 때

- 콘텐츠와 타이밍을 인수로 받는 작은 단위를 만든다. 예: `DrawIllustration`, `PictogramAction`, `PhraseReveal`, `ResultTransform`, `ScreenshotFocus`, `SharedObjectTransition`.
- 주입할 정보: 화면 비율, 색상 토큰, 관련 대상, 등장·정착·강조·퇴장 시간, 음성 큐, 결과 읽기 구간. 숫자와 문장을 컴포넌트에 하드코딩하지 않는다.
- 아이콘·일러스트·본문·주석 레이어를 구분해 움직인다. 같은 `fadeUp` 함수를 모든 요소에 적용한 뒤 모션을 완료했다고 판단하지 않는다.
- HyperFrames는 해당 프로젝트 버전의 타임라인·시크 규칙을 지킨다. GSAP 타임라인에서 같은 시간은 같은 상태로 그려지고, 무한 루프·페이지 로드 시각·임의 난수에 의존하지 않게 한다. 크기와 대상 위치는 초기 레이아웃에서 계산해 고정한다.
- Remotion을 사용하는 경우 프레임 기반 상태로 같은 설계를 구현한다. 엔진별 기술 규칙을 혼합하지 않는다.
- 구현 방법 확인은 로컬 가이드와 설치된 도구부터 확인하고, 외부 라이브러리/API 정보가 필요하면 해당 공식 자료로 확인한다.

## 리디자인 검수

- 연속 장면을 컨택트시트로 확인한다. 축소했을 때 같은 제목과 큰 박스만 반복되어 보이면 구도부터 수정한다.
- 대표 연속 구간을 실제 재생한다. 요소 등장 후 아무 변화 없이 오래 기다리거나, 반대로 읽기 전에 사라지는 구간을 찾아 조정한다.
- 스타일 1은 실제 화면의 핵심과 전후 차이가 읽히는지, 스타일 2는 큰 일러스트가 설명을 맡는지 본다. 스타일 2에서 단순 장식만 늘었다면 글을 시각적인 과정으로 바꾼다.
- 전환 양끝, 강조 직전·직후, 결과 유지 프레임을 확인한다. 텍스트 선행, 대상을 가리키는 위치, 자막 안전 영역을 검수한다.
- 승인된 목소리·속도·호흡은 시각 리디자인 때문에 변경하지 않는다. 새 시각본은 기존 승인 파일을 보존한 별도 버전으로 만든다.

## 2026-10 확정한 화면 시스템

제미나이 스킬 롱폼(2026-10-05)에서 사용자가 "무척 마음에 든다"고 한 구성이다. 스타일 1의 기본값으로 쓴다.

**배경과 면**

- 팔레트 02 기준 `#14213D` 단색 배경, 아주 옅은 점 패턴만 천천히 흐른다. 흰 배경 + 회색 사선 띠·노란 선의 분할 배경은 "어색하고 이상하다"고 기각되었다. 네이비만 쓰면서 정적이면 지루하다는 9월 피드백도 함께 적용해, 움직임은 컴포넌트에서 낸다.
- 정보는 흰 카드, 캡처 창, 옐로 강조 면 위에 올린다. 배경 위에 바로 놓는 글자는 흰색, 보조 글자는 `#C9D2E3` 정도의 밝은 회청색. 남색 글자·남색 띠를 배경 위에 그대로 두지 않는다(표 머리글, 라벨 띠, 말풍선 포함).
- 캡처는 창 모양으로 감싼다: 밝은 회색 상단 바 + 서비스 공식 로고·이름. 서비스 로고가 배경색과 같으면 배경에서는 흰색으로, 밝은 바에서는 어둡게 표시한다.
- 상자 높이는 내용에 맞춘다. 고정 높이로 아래쪽이 비면 답답하지 않을 만큼의 여백만 남기고 줄인다.

**파트 구분**

- 장이 바뀔 때 전체 화면 장 전환(옐로·남색 면이 쓸고 지나가며 큰 번호 + 장 제목)을 넣는다.
- 상단에 단계 표시(예: 양식 · 대화 · 받은 파일 · 비교)를 두고 현재 단계를 옐로로, 지난 단계를 흰 테두리로 표시한다.
- 배경 오른쪽 위에 장 번호를 아주 옅은 외곽선 숫자로 둔다.

**박스·연결선·퇴장 (assets/motion/box-motion.js)**

| 동작 | 쓰는 곳 | 규칙 |
| --- | --- | --- |
| `dbox` 선이 영역을 그린 뒤 펼침 | 카드, 표 칸, 비교 열 | 선이 약 70% 그려졌을 때 내용이 왼쪽부터 펼쳐진다. 펼치는 동안에도 둥근 모서리와 그림자 유지 |
| `outline` 테두리만 그렸다 사라짐 | 비교 중 하나 짚기, 표의 칸 차례 강조 | 대상의 네 모서리 곡률을 그대로 따라감. 오래 강조할 때는 대상 안쪽에 붙은 테두리 요소를 쓴다 |
| `link` 곡선 화살표 | 단계 흐름, 출처 → 설치 목록 | 장면이 끝나면 함께 사라짐. 간격 45px 미만이면 그리지 않음(오타처럼 보임) |
| `flyOut` 날아가며 퇴장 | 장면 정리 | 한꺼번에 사라지지 않게 순서대로 |
| 채우기·카운트 | 진행 막대, 숫자 | 단계가 진행될 때만 |

**매끄러운 강조를 위한 기준**

1. 형광펜 박스: 테두리를 먼저 그리고, 채움은 테두리가 거의 끝난 뒤 옅게 차오른다. 테두리와 채움이 동시에 켜지면 끊겨 보인다.
2. 밑줄: 얇은 선 대신 글자 뒤에 깔리는 반투명 형광펜 띠, 끝은 부드럽게 감속.
3. 캡처를 확대·이동한 경우 카메라가 멈추고 약 0.2초 뒤에 강조를 그린다.
4. 박스 등장은 선 그리기와 펼치기가 겹치되 급하지 않게, 외곽선은 천천히 사라진다.
5. 가속·감속 곡선은 영상 전체에서 한 세트(그리기 power2.inOut, 등장 expo.out, 퇴장 power3.in)로 맞춘다.

**자주 나온 결함**

- 로드 시점에 잰 테두리가 글꼴 로드 뒤 박스와 어긋남 → 글꼴 로드 후·크기 변화 때 다시 잰다.
- 펼치기 마스크가 남아 박스 밖 태그·뱃지가 잘림, 네모 마스크가 그림자를 각지게 자름 → 둥근 마스크, 끝나면 해제.
- 연결선의 둥근 끝이 그려지기 전부터 점으로 보임 → 시작 전까지 숨김.
- 같은 id를 가진 요소가 다른 구간에 있어 한 구간용 색 규칙이 다른 구간까지 바꿈 → 테마 덮어쓰기는 구간 클래스로 범위를 제한한다.
- 연결선·외곽선이 다음 장면까지 남음 → 장면 끝 시각에 자동으로 사라지게.

**스킬·도구를 다루는 영상의 마무리 예**

정리 → "그럼 이 영상은 어떻게 만들었을까요? 이것도 스킬로 만들었어요." → 작업 흐름(기획은 함께 → 리서치 → 윤문 → 모션 → 검토 1차 AI·최종 본인 → 발행) → 가져온 스킬·도구·MCP → 자동화 범위(예약하면 전 과정 자동도 가능하지만 최신·신뢰가 중요한 영상은 기획·검수를 직접, 틀이 정해진 정기 콘텐츠는 전자동도 가능) → 다음 영상 예고. 화면은 단계 노드가 차례로 그려지고 진행 막대가 채워지는 흐름도.
