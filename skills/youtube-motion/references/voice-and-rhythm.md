# 본인 음성과 롱폼 호흡

## 현재 승인 상태

2026-09-27 사용자 피드백으로 확정된 사항:

- Google에 등록된 **사용자 본인 음성**을 사용한다. 초기 Kore 여성 음성 승인보다 이후 본인 음성 사용 요청이 우선한다.
- 별도 동의 녹음을 받아 프로필 등록이 성공했다. 같은 승인 프로필의 재사용에 동의 문장을 다시 요청하지 않는다.
- 음색 유사도는 사용자가 청취해 판단한다. 등록 성공을 완벽한 음색 일치로 표현하지 않는다.
- 차분하고 친절하며 신뢰감 있는 설명 톤. 과장된 광고 억양, 기계적인 문장 끝, 늘어지는 말하기를 피한다.
- Aside 기존 수정본을 1.25배로 만든 버전의 **말하는 속도는 승인**되었다.
- 사용자는 **48초 숏폼 리듬이 좋다**고 했고, 숨가쁘다는 지적은 **롱폼**에 대한 것이었다.

`1.25배`는 과거 특정 원본과의 상대값이다. 이미 빨라진 음성에 다시 1.25를 적용하지 않는다. 새 원고는 승인본의 발화 리듬을 참고하고, 차분하다는 이유로 느리게 읽지 않는다.

## 롱폼 쉼 기준

기존 자연스러운 무음을 포함한 **최소 총 쉼**을 기준으로 한다.

| 의미 경계 | 총 쉼의 출발점 |
| --- | --- |
| 일반적인 완결 문장 뒤 | 0.4초 |
| 기억해야 할 핵심·결론 뒤 | 1.0초 |
| 새로운 주제로 넘어가기 전 | 1.2초 |
| 별도 의미 경계가 없는 완결된 장면 전환 | 0.65초 |

- 여러 조건이 겹치면 합산하지 않고 해당 경계에 필요한 가장 긴 값을 쓴다. 장면이 바뀐다는 이유로 진행 중인 문장을 끊지 않는다.
- 추가할 쉼 = `max(0, 목표 총 쉼 - 이미 존재하는 쉼)`.
- 이미 자연스럽게 더 긴 쉼이 있으면 기계적으로 줄이지 않는다. 긴 정적이 방해되는 경우만 맥락을 보고 조정한다.
- 쉼의 위치는 문장과 생각의 끝이다. 자막 줄바꿈, 한 큐의 끝, 쉼표, 짧은 연결 어미마다 넣지 않는다.
- 핵심 문장만 강조용 쉼을 갖게 한다. 매 문장 뒤 1초씩 멈추게 하지 않는다.
- 그동안 해당 자막과 결과 화면을 유지한다. 다음 장면·제목·나레이션이 먼저 시작되지 않게 한다.
- 최종 길이가 늘어나는 것은 허용한다. 원래 요청된 분량을 채우거나 맞추려고 승인된 발화를 다시 늘이거나 가속하지 않는다. 길이가 엄격한 경우 원고·구성을 조정한다.
- 이 규칙은 사용자에게 설명하기 위한 제목이 아니라 내부 편집 기준이다. “멈출 지점” 같은 문구를 영상에 노출하지 않는다.

## 숏폼 마무리

- 활용 요청문 뒤에 효용을 덧붙이는 원고라면, 앞 문장에서 끊긴 것처럼 읽지 않고 하나의 설명으로 연결한다. 마지막 문장은 결론에 맞는 자연스러운 하강 억양으로 마친다.
- 마지막 발화가 끝난 뒤 핵심 결과와 효용 문구를 약 1초 유지하는 것을 출발점으로 삼는다. 클로드 통합 숏츠1 v6는 약 0.94초를 유지했다. 이는 참고값이며 모든 숏츠의 길이나 호흡을 고정하는 규칙은 아니다.
- 마지막 받침·호흡을 잘라 시간을 맞추지 않는다. 이미 있는 말끝 여유를 포함해 유지 시간을 계산하고, 종료 직전에 다음 장면이나 새 문구를 띄우지 않는다.

## 수정 방식

1. 현재 승인본, 원음, 타임라인, SRT를 찾고 변경 범위를 기록한다. 롱폼만 수정하면 숏폼의 해시를 먼저 기록할 수 있다.
2. 실제 오디오의 단어 끝과 무음 영역을 찾는다. 한국어 ASR 결과는 원고와 대조하며, 자동 인식 문장을 그대로 새 원고로 삼지 않는다.
3. 의미 경계별 목표 쉼을 배치한다. 발화가 끝나지 않은 곳, 받침·호흡 소리가 남은 곳을 잘라내지 않는다.
4. 추가 쉼이 필요한 경우 조용한 경계에서만 삽입한다. 말소리의 속도, 피치, 순서, 음량을 보존한다. 가능하면 음성을 재생성하지 않는다.
5. 타임코드 이동량을 한 타임라인에 기록한다. 동일한 이동을 장면·자막·모션·오디오에 모두 적용한다.
6. 정적 화면은 같은 상태를 유지한다. 움직이는 캡처나 실사는 필요하면 읽을 수 있는 홀드 화면으로 전환하며 어색한 중간 동작 프리즈를 피한다.
7. 최종 AAC 등 인코딩 후에도 실제 쉼과 오디오 연속성을 확인한다. SRT가 최신 타임라인을 반영하는지 확인한다.
8. 요청 범위 밖 파일이 변하지 않았는지 확인한다. 승인된 숏폼에는 롱폼 쉼을 일괄 적용하지 않는다.

원시 PCM을 삽입해 처리한다면 삭제한 삽입 구간을 제외한 발화 샘플이 원본과 같은지 비교하는 방식이 유용하다. 최종 인코딩에는 손실이 있으므로 동일 바이트를 요구하지 않고 파형 상관도·길이·청취 가능한 검토 수단을 함께 사용한다. 쉼 편집 중 모노/스테레오 변환으로 음량이 바뀌지 않도록 채널 구성과 게인을 보존한다.

## 새 음성 생성

- 현재 프로젝트의 Google TTS 도구와 비공개 프로필 포인터를 재사용한다. 로컬 위치는 [로컬 프로젝트](local-workspace.md)를 참고한다.
- 모델명은 프로젝트 설정을 읽는다. 현재 작동한 모델이나 API 버전은 영구 보장으로 간주하지 않는다. 오류나 변경이 있으면 공식 문서를 확인한다.
- 키와 음성 프로필 값을 채팅·로그에 출력하지 않는다. 개인 음성·동의 녹음을 다른 서비스로 임의 전송하지 않는다.
- 본인 음성을 사용할 수 없으면 문제를 설명한다. 다른 목소리로 바꾸고 본인 음성이라고 납품하지 않는다.
- 다른 화자의 음성이나 다른 서비스로 새로 등록하는 상황은 기존 동의 범위와 별개다. 실제 필요한 동의와 자료만 요청한다.
- 원고는 발음, 숫자 읽기, 영문 제품명, 문장 끝 억양을 확인한다. 강조를 위해 모든 낱말을 강하게 읽게 하지 않는다.
- 수정 없는 구간은 캐시를 활용한다. 프로필·원고·스타일·모델이 다른 음성을 같은 캐시로 재사용하지 않는다.
- 오디오 파일의 단어 시간을 기준으로 의미 단위 자막을 만든다. 빠른 말하기와 넉넉한 쉼을 동시에 구현한다.
