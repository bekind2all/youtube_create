# 사용 조건과 강조 효과의 정밀 검수

## 주장, 공식 지원, 실제 구현을 맞춘다

“한 번만 연결”, “계속 자동”, “항상”, “누구나 무료”, “바로 발행” 같은 표현은 조건이 빠졌는지 확인한다. 공식 API가 지원한다고 현재 만든 앱이 그 기능을 구현한 것은 아니다.

관련 주장마다 짧게 기록한다: **최종 문구 / 공식 URL·확인일 / 현재 코드 또는 실행 근거 / 필요한 조건 / 미검증 범위**. 정보가 바뀌는 주장은 현재 공식 원문을 확인한다. 문구를 바꾸지 않는 시각 수정에는 이전 검증을 재사용할 수 있다.

연결·인증이 핵심인 영상은 아래 중 해당하는 부분을 확인한다.

- 사용자 동의, 액세스 토큰, 갱신 토큰, 브라우저 세션 저장은 서로 다르다. 동의가 남아 있어도 현재 앱의 액세스 토큰은 만료될 수 있다.
- 현재 코드의 토큰 보관 위치, 만료 처리, 자동 갱신 구현 여부와 새로고침·재접속 후 동작을 확인한다. 권한 철회·관리자 정책 등 추가 조건은 주장의 범위에 필요할 때 확인한다.
- 특정 시연 앱이 다시 연결해야 한다는 사실을 모든 Google 연동 앱의 공통 제한으로 확대하지 않는다. 재연결이 매번 전체 동의 절차를 뜻하는지도 구분한다.
- 예: 메모리에만 액세스 토큰을 보관하고 갱신 로직이 없는 앱은 “현재 시연 앱은 새로고침·재접속·인증 만료 시 다시 연결해야 합니다”처럼 구현 범위를 밝혀 설명한다. 다른 앱에 이 문장을 자동 복사하지 않는다.

Google 토큰 모델을 조사할 때의 공식 출발점: [토큰 모델](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [인증 모델 선택](https://developers.google.com/identity/oauth2/web/guides/choose-authorization-model). 실제 제작 시점의 문서와 프로젝트 코드를 함께 확인한다.

### 검증했다고 말할 수 있는 범위

| 확인한 것 | 이것만으로 확인되지 않는 것 |
| --- | --- |
| 모바일 크기로 표시한 웹 화면 | Android 실기기의 마이크·브라우저·권한 동작 |
| 음성 파일 업로드와 해석 성공 | 실시간 마이크 녹음부터 저장까지의 전체 흐름 |
| API로 일정 생성 후 다시 읽기 | 휴대폰 알림이 해당 시각에 실제로 도착함 |
| 캘린더에 30분 전 알림 설정 저장 | 알림 권한·동기화·기기 설정과 무관한 수신 보장 |
| 공식 데모 화면 확보 | 제작자가 같은 동작을 직접 실행함 |

잘못된 사실을 고칠 때는 원고·나레이션·화면·자막·앱 시연 문구·검토 자료에 남은 표현을 함께 찾는다. 필요 구간의 음성만 다시 만들고, 영향 없는 승인 음성을 보존한다. 그림이나 전환이 사용자 확인 없이 실제 행동이 자동 실행된다는 오해를 만들지 않게 한다.

## 글자에 붙어 있는 강조 효과

1. 실제 로컬 폰트를 로드한 뒤 대상 글자를 측정한다. 전체 제목 박스 폭 대신 강조할 구절의 폭을 쓴다. 줄바꿈이 있으면 줄마다 분리한다.
2. 대상과 밑줄을 같은 위치 기준 컨테이너에 둔다. 글자 교체·크기·비율 변경 시 다시 계산한다. 이미 transform으로 축소된 화면에서 얻은 픽셀값을 원래 좌표처럼 쓰지 않는다.
3. 둥근 선 끝은 경로의 끝보다 반 선 두께만큼 더 나간다. 이 길이와 여백을 빼고 경로를 만든다. 글자의 아랫부분과 겹치지 않도록 간격을 둔다.
4. SVG의 CSS 폭, viewBox, 경로 길이의 단위를 일치시킨다. 작은 viewBox를 크게 늘린 상태에서 `vector-effect: non-scaling-stroke`와 dash 길이를 섞으면 선이 점선처럼 보일 수 있다. 실제 글자 폭으로 viewBox와 경로를 만든 다음 `getTotalLength()`를 구한다.
5. 글자가 읽히는 상태로 정착한 뒤, 해당 발화 큐에 맞춰 그린다. 대상이 사라지거나 다음 장면으로 넘어가면 효과도 함께 사라진다. 화살표는 출발·도착 대상이 모두 보여야 한다.
6. 캡처 주석은 원본의 대상 위치와 크롭·확대 변환을 함께 계산한다. 임의 화면 좌표를 다른 캡처에 재사용하지 않는다.

`assets/motion/fit-text-underlines.js`는 한 줄 구절용 기하 보조 함수다. 프로젝트의 컴포넌트 범위로 불러오거나 인라인하고, `await document.fonts.ready` 뒤, 타임라인·transform 설정 전에 `fitTextUnderlines(root)`를 호출한다. 대상 컨테이너는 `position:relative; display:inline-block; width:max-content; padding-bottom:30px`로 시작할 수 있다. `.text-target`은 실제 구절, `.anchored-underline`은 같은 컨테이너 안의 SVG이며 `left:0; bottom:0; width:100%; height:27px`로 둔다. 경로는 `fill:none; stroke:currentColor; stroke-width:9; stroke-linecap:round`를 사용한다. 시간과 색은 장면에서 지정한다. 다중 행·회전·스케일 상태를 자동 지원한다고 가정하지 않는다.

## 최종 렌더로 판정한다

- 강조 시작 직전, 그리는 도중, 완료 후를 **최종 MP4**에서 확인한다. HTML 스냅샷만으로 인코딩 결과를 대신하지 않는다.
- 글자 바깥으로 삐져나옴, 효과가 먼저 나옴, 대상 이동 후 위치가 어긋남, 점선화·누락을 확인한다.
- 휴대폰 크기(예: 360×640)에서 장면의 주인공과 결과가 알아보이는지 본다. SVG 개수나 코드에 아이콘이 있다는 사실은 합격 기준이 아니다.
- 시각 수정이면 기존 음성·타임라인을 유지하고 이전 파일을 남긴다. 검수 완료와 사용자의 최종 승인을 구분한다.
