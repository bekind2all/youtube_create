# 완성 영상 승인 후 YouTube 업로드

## 사용자와 합의한 작업 범위

사용자는 **완성 영상 승인 → 유튜브 제목·설명·썸네일 제작 → YouTube 업로드**까지 하나의 제작 흐름으로 위임했다. 완성본을 승인하면 이 후속 작업을 바로 수행한다. 제목이나 썸네일을 따로 요청할 때까지 기다리거나 같은 업로드 권한을 다시 묻지 않는다.

- 스토리보드 승인은 영상 제작 승인이다. 실제 완성 영상을 검토한 뒤의 최종 승인과 구분한다. 특정 컴포넌트에 대한 긍정적인 평가나 일부 수정 요청만으로 영상 전체가 승인됐다고 판단하지 않는다.
- `production-status.json`에 승인한 파일·버전과 사용자의 승인 근거를 남긴다. 사용자가 이번에는 파일만 만들라고 하거나 업로드를 보류하면 그 지시를 우선한다.
- 대상 채널, 공개·비공개·일부 공개, 예약 시각은 기존 대화와 실제 사용자가 선택한 설정을 따른다. 이미 정해진 설정을 되묻지 않는다. 대상이나 공개 범위를 결정할 근거가 없으면 필요한 미정 정보만 확인한다. 공개 발행까지 승인된 경우 저장 단계에서 별도 승인을 추가로 요구하지 않는다.
- 이 흐름은 해당 승인 영상의 YouTube 업로드를 위한 것이다. 다른 플랫폼 게시나 반복 업로드 자동화로 확대하지 않는다.

## 업로드 자료 제작

1. **제목:** 서비스·주제와 시청자가 얻을 효용을 짧게 담는다. 호기심을 주되 영상에 없는 성능·시간 절약·전면 제공을 약속하지 않는다. 내부 파일명과 버전 번호를 제목으로 쓰지 않는다.
2. **설명:** 첫 문단에 핵심 변화와 효용, 이어서 바로 쓸 요청문이나 활용 상황을 담는다. 중요한 플랜·베타·단계적 적용 조건과 공식 출처를 필요한 만큼 덧붙인다. 영상에 없는 비교나 새 주제로 늘리지 않는다.
3. **해시태그·검색 태그:** 영상과 직접 관련된 것만 고른다. 자동 추천 항목을 그대로 모두 추가하지 않는다.
4. **썸네일:** 영상과 별도로 완성 이미지를 만든다. 선택 팔레트, 읽기 쉬운 짧은 핵심 문구, 눈에 띄는 한 시각 요소를 사용한다. 서비스·제품 영상이면 [공식 로고 기준](brand-and-motion.md#공식-서비스제품-로고)을 적용한다. 썸네일에 나온 결과와 약속이 본편에서 확인되어야 한다.
5. **검수:** 제목·설명·썸네일 문구에 `humanize-korean`을 적용하고 원고·출처와 의미를 대조한다. 썸네일은 휴대폰 목록 크기에서 글자와 로고가 읽히는지, 한글 오탈자·잘림이 없는지 본다. 파일과 최종 프롬프트·출처는 해당 에피소드에 보관한다.

Shorts는 세로형 썸네일을 준비한다. 실제 업로드 시점의 YouTube 도움말과 현재 스튜디오 화면에서 지원 형식·크기·업로드 방법을 확인한다. 예전의 기능 제한을 현재도 적용되는 것으로 단정하지 않는다.

## 실제 업로드와 완료 확인

- 연결된 YouTube 도구나 현재 스튜디오에서 채널과 대상 영상을 확인한다. 같은 승인본의 초안이 이미 있으면 제목·설명·썸네일을 그 초안에 적용한다. 파일명·버전·영상 길이 등으로 대상을 구분하고 중복 업로드를 피한다.
- 승인한 MP4, 제목, 설명, 해시태그·검색 태그, 썸네일을 적용한다. 이미 설정된 제목·설명은 내용이 맞으면 유지한다. 시청자층·유료 프로모션·합성 콘텐츠 등 질문에는 실제 제작 내용과 사용자 정보에 근거해 답한다.
- 실제 저장 상태, 적용된 썸네일, 제목·설명, 동영상 URL과 공개·예약 상태를 확인한다. 사이트에 변경을 적용했으면 사용자가 확인할 수 있는 화면을 저장해 결과에 포함한다. 비공개 저장을 공개 발행 완료라고 보고하지 않는다.
- 로그인·확장 프로그램 파일 접근·계정 제한 등으로 막히면 완성한 자료는 보존하고, 실패한 단계와 필요한 조치를 구체적으로 알린다. 성공했다고 기록하거나 같은 실패를 계속 반복하지 않는다. 조건이 해결되면 기존 초안에서 이어간다.
- 상태 파일에는 자료 경로, 승인 근거, 채널·영상 식별 정보, 입력·저장·공개 상태와 실제 막힌 지점을 구분해 남긴다. 로컬 파일 제작만 완료된 상태와 YouTube 업로드 완료 상태를 혼동하지 않는다.
