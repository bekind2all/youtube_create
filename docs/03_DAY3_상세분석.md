## 0. 한 줄 요약

DAY3는 **"만족한 결과와 그 결과까지의 여정을 SKILL.md로 남기고, 새 폴더·새 대화에서 처음부터 돌려 보고, 안 되면 규칙의 근거를 묻고 깎고, 민감정보를 빼고 GitHub에 공개한다"**는 절차다. 강사가 실제 수업 중에 스킬 생성이 20분 넘게 지연되고 AI가 질문을 하며 멈추는 장면 `[53:10]`~`[57:00]`이 그대로 녹화되어 있어서, "스킬화가 딸깍이 아니다"라는 점을 가장 솔직하게 보여 주는 편이기도 하다.

당신 프로젝트 기준: `AGENTS.md`+`design.md`+`tools/*.py`+`render-template/` 조합이 이미 "스킬"이다. DAY3에서 가져올 것은 (1) 규칙 3층 분리(원칙/고정값/통과조건), (2) 새 대화 재현 테스트, (3) 규칙 근거 5질문, (4) 배포 전 민감정보 점검이다. 그리고 `[50:41]` "저는 리모션보다 하이퍼프레임을 쓴다"는 강사 선택의 이유가 당신의 도구 선택 질문에 답을 준다.

## 2. 구간별 상세

### 2-1. [02:45–09:20] 목적 → 레퍼런스 → 뜯어보기 → 활용 → 결과 → 스킬

- `[02:47]` "대화가 스킬이 되는 순간". `[03:08]` "완벽한 스킬로 만드는 건 시간이 많이 드는 과정이라 … 일단 완성하고 **완료주의**로 가고 공유하고 각자 커스텀."
- `[03:49]` **"가장 필요한 게 목적 … '인스타 자동화하고 싶어'보다 '후킹 앞단을 도와주는 대본 작성기를 만들고 싶어'처럼 디테일한 목적."**
- `[04:33]` "뭘 뜯어볼지 정해 주는 건 내 역량 … 색감을 볼지, 헤드카피를 볼지, 메뉴 구성을 볼지. 그리고 뜯어본 걸 어떻게 활용할지 정의해 주는 게 실력."
- `[06:53]` 딱샘 사례: 유치원 홈페이지, 잡코리아, 교사 커뮤니티 앱, 키즈노트, 네이버 카페 유료 디자인 판매 구조까지 리서치. 색상 몇 가지 쓰는지, 폰트, 메뉴 구성. `[08:30]` 네이밍도 배민·야놀자 레퍼런스로.

**적용:** 당신의 목적 문장은 이미 명확하다(BRIEF.md: "오퍼스 5.5의 비용 수치를 정확히 읽고 내 반복 업무로 도입 효과를 확인한다", 롱폼 3~5분 + 숏폼 2~3개). 이번 요청("일러스트 레퍼런스 스타일 반영")은 목적이 아니라 **스타일 제약**이므로, "뭘 뜯어볼지"를 명시해야 한다: 15장에서 뜯어볼 것 = 팔레트, 선, 질감, 타이포, 구도. 뜯어보지 않을 것 = 각 그림의 소재(커피, 패션, 인물 포즈).

### 2-2. [09:20–12:50] 스킬 승격 프롬프트

- `[09:18]` "스킬로 승격시켜 주는 프롬프트를 고군분투해서 만들었다"(노션/카톡 배포). 입력 위치: **결과물을 만든 그 대화창**.
- `[11:54]` 한 대화창에서 여러 작업을 한 수강생 → "앞으로는 나눠서. 아니면 프롬프트에 '우리가 만든 편집 결과물 final.mp4에 대한 것'이라고 파일명을 특정."

**적용:** 당신은 Codex 세션에서 만든 것이므로 대화 로그가 아니라 **파일이 근거**다. 강사의 "대화 로그 채굴" 대신 `episodes/2026-09-22-opus-5-5/` 안의 BRIEF/STORYBOARD/check-output/build-report가 로그 역할을 한다. 이게 오히려 더 재현성이 좋다(대화는 유실되지만 파일은 남는다).

### 2-5. [33:30–41:40] 스킬은 만든 뒤가 시작이다

**적용 — 당신 프로젝트의 "새 대화 테스트"는 이렇게 한다:**
1. 새 폴더에 `ai-news-video`를 clone(에피소드 폴더 제외).
2. 새 세션에서 "GPT-6 Astra 발표(주제선정.md 2순위)로 episodes/2026-XX-astra를 만들어 롱폼 1 + 숏폼 3을 built_pending_checks까지 진행해"라고만 지시.
3. 막히는 지점(키 누락, 폰트 경로, check 오류)이 곧 스킬에 빠진 정보다. 이번에 내가 이 환경에서 재현하면서 발견한 누락(05 문서)이 그 첫 목록이다.

## 3. DAY3에서 "그대로 따르지 말 것"

1. **"AI 자기평가 90점 넘으면 합격"**: 자기 점수는 근거가 아니다. 당신 AGENTS.md의 검증 조건(화면/자막/음성/출처/MP4)으로 대체.
2. **"질문하지 말고 알아서 해"**: 모호한 조건을 없애지 않는다. 기본값으로 정해도 되는 것(파일명, 비율)과 반드시 물어야 하는 것(원본 삭제, 외부 게시)을 스킬에 나눠 적는다.
3. **대화 로그를 스킬 재료로**: 로그는 유실된다. 파일(BRIEF/STORYBOARD/check-output)이 재료여야 한다 — 당신은 이미 그렇게 하고 있다.
4. **99만 원 판매 사례**: 시장성 판단 근거로 쓰지 않는다.

## 4. DAY3에서 당신 프로젝트에 바로 넣을 것

1. **규칙 3층 분리**로 design.md 재편(원칙/고정값/통과조건). 일러스트 스타일도 같은 3층으로 추가.
