# 결론 요약 — 레퍼런스 스타일 영상, Remotion/HyperFrames로 가능한가

## 1. 답

**가능하다. 둘 다 이 환경에서 실제로 설치·렌더까지 확인했다.** 그리고 당신은 이미 HyperFrames로 파이프라인의 90%를 만들어 놓았다(`ai-news-video`: Python 생성기 → 장면 HTML → `hyperframes check/render`). **HyperFrames를 유지**하고, 아래 "지금 막힌 것" 한 줄을 고친 뒤, 일러스트를 "부품 SVG"로 얹으면 된다.

| 질문 | 답 | 근거 |
|---|---|---|
| HyperFrames로 되나 | 된다. 0.8.79에서 init → check → render 10초 MP4 성공 | 05 문서 2-1 |
| Remotion으로 되나 | 된다. 4.0.529에서 당신 팔레트로 3초 한국어 장면 렌더 성공 | 05 문서 2-2, `assets/tool-tests/remotion_scene_3s.mp4` |
| 어느 쪽 | HyperFrames. 이유: 당신 생성기가 HTML을 찍어내는 구조, CLI 검사(check/snapshot)가 페이스리스 자동화에 유리, 강사도 DAY3 `[50:41]`에서 같은 선택 | 05 문서 3절 |
| 레퍼런스 스타일이 코드로 되나 | 된다. 15장의 공통 문법(균일한 모노라인, 종이+잉크+강조 1색, 비운 면, 스티커 후광, 모션 마크)은 전부 SVG stroke/fill + GSAP draw-on으로 표현 가능한 것들이다 | 04 문서 2·4절 |
| 지금 당신 프로젝트가 막힌 이유 | `build_video.py` 정규식 한 줄(`\\{` → `\{`) 때문에 sub-composition 7개에 @font-face가 남아 번들이 17 MB가 되고, HyperFrames CLI의 정규식이 스택 오버플로 | 05 문서 4절 |

## 2. 지금 막힌 것 — 한 줄 패치

```diff
# tools/build_video.py  sub_css()
-    s=re.sub(r"@font-face\\{[^}]+\\}", "", s)
+    s=re.sub(r"@font-face\{[^}]+\}", "", s)
```

이 컨테이너에서 당신 Drive 프로젝트를 그대로 복원해 **같은 오류를 재현하고, 이 패치만 적용해 check 통과(ok:true, contrast 65/65) → longform 282.5초 MP4(5분 47초 렌더) + short-01 42.5초 MP4까지 렌더했다.** 증거: `assets/tool-tests/ai-news-video-check/`(패치, check 전후 JSON, 스택트레이스, 렌더 프레임 3장).

남는 경고 2개(`No deterministic font mapping for: inherit`, `timeline_track_too_dense`)는 무해하고, `font-family: Pretendard`로 바꾸면 오히려 lint error가 나는 것도 실측했다. 둔다.

## 3. 세 영상에서 가져온 것 중 당신에게 가장 중요한 다섯 가지

1. **레퍼런스는 "소재"가 아니라 "문법"을 뽑는다** (DAY1 `[56:52]`, `[66:45]`). 커피·고양이가 아니라 선 굵기·색 수·면 비율·후광·모션 마크. → 04 문서가 그 결과물이고, design.md에 붙일 3층(원칙/고정값/통과조건) 초안까지 썼다.
2. **피드백은 장면이 아니라 규칙을 고친다** (DAY2 `[38:42]`~`[40:29]`, 회색 막대 사례 `[25:15]`). "컵이 크다"가 아니라 "그림 높이 상한을 520으로". → 06 문서 P4 프롬프트.
3. **디자인 소스는 있어야 한다** (DAY1 `[22:11]`) → 인물·소품을 매번 생성하지 말고 **부품 세트 8~15개를 SVG로** 만든다(DAY2 `[50:33]` 곰 48장 분류 = 레퍼런스 05의 스티커 시트). 이것이 도구(HyperFrames/Remotion)와 무관한 자산이다.
4. **덮어쓰지 말고 버전을 남긴다** (DAY2 `[47:37]`) → `renders/final_v{NNN}.mp4`, build-report에 빌드 번호.
5. **대화를 스킬로 남기고 새 창에서 검증한다** (DAY3 `[39:59]`, `[58:00]`) → design.md 일러스트 절이 완성되면 GPT-6 Astra 같은 **다른 에피소드**를 새 채팅에서 만들어 규칙만으로 같은 그림이 나오는지 본다(06 문서 P6).

## 4. 다음 3가지 행동 (순서대로)

1. **패치 적용 → check → render** (30분). 위 diff 적용, `python3 tools/build_video.py episodes/2026-09-22-opus-5-5`, 각 폴더에서 `npm run check` → 통과하면 `npm run render`. Windows에서는 Chrome headless shell·ffprobe가 자동으로 잡히지만 안 되면 `HYPERFRAMES_BROWSER_PATH`, `HYPERFRAMES_FFPROBE_PATH`로 지정.
2. **부품 시트 1장** (반나절). 04 문서 4-6절의 부품 8개를 SVG로 만들어 한 화면에 모아 PNG 1장으로 렌더하고 눈으로 본다. 선 굵기 9px·색 3개·면 비움이 지켜졌는지만 본다. 프롬프트는 06 문서 P2.
3. **파일럿 2장면** (반나절). scene-01 타이틀과 scene-02 "40%" 장면에만 `illustration` 슬롯을 넣고 check → snapshot → 피드백(P4 양식) → design.md 고정값 수정. 통과하면 나머지 장면으로 확장.

이 셋이 끝나면 06 문서 5~7단계(새 에피소드 재현, 스킬화, 민감정보 제거 후 GitHub)로 간다.

## 5. 이번에 확인하지 못한 것 (솔직하게)

- 레퍼런스 15장 중 **5장(09·10·11·12·14)은 못 봤다.** Drive MCP 응답이 인라인 base64로만 와서 바이트 복원이 안 됐고, 직접 다운로드는 프록시가 막았다. 04 문서의 공통 문법은 본 10장 기준이며, 나머지 5장을 보고 바뀔 수 있는 지점을 각 절 끝에 적었다. **당신이 로컬에서 5장을 보고 04 문서 2절의 표에 행을 채우면 된다.**
- 세 영상의 **화면(프레임)은 못 봤다.** 자막 전문(7,101 세그먼트, 4시간 52분)만 읽었다. 강사가 화면에서 보여 준 것은 발화로 추정했고, 문서에 `[mm:ss]`를 달아 두었으니 의심스러운 곳은 그 시각으로 가서 확인하라.
- `/watch` 스킬은 당신 Windows 경로에 있어 로드하지 못했고, 같은 절차를 수동으로 했다.
- Remotion·HyperFrames 검증은 리눅스 컨테이너 기준이다. Windows에서의 차이는 Chrome/ffprobe 경로뿐일 가능성이 크지만 보장은 못 한다.
