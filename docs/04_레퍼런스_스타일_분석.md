# 일러스트 레퍼런스 15장 → 영상 스타일 규칙

- 출처: Drive 폴더 루트의 `일러스트 레퍼런스 01~15`(jpg 14장 + png 1장). Drive MCP로 원본 바이트를 받아 **10장(01·02·03·04·05·06·07·08·13·15)은 직접 봤다.** 나머지 5장(09·10·11·12·14)은 이 컨테이너에서 받지 못했다(11은 전송 중 잘려 손상, 09·10·12·14는 MCP 응답이 인라인으로만 와서 바이트 복원 불가, Drive 직접 HTTP는 프록시 403, OCR 텍스트도 비어 있음). 아래 카드에서 그 5장은 "미열람"으로 표시했고, 공통 문법은 본 10장으로만 뽑았다. 5장을 보고 나서 규칙이 바뀔 수 있는 부분은 각 절 끝에 적었다.
- 이 문서는 그림을 베끼기 위한 것이 아니다. DAY1 `[66:45]`의 원칙대로 **소재(커피, 패션, 고양이)가 아니라 문법(선·색·질감·구도·타이포)**을 뽑아 당신 design.md에 넣을 규칙으로 바꾼다.
- 당신의 현재 design.md 토큰(#F4F0E7 바탕, #222820 본문, #AB411F 강조, #536052 보조, Pretendard 400/800)과 충돌하는 부분은 "선택지"로 적었다. 결정은 당신 몫이다.
- 비교 기준으로 당신의 현재 렌더 프레임(05 문서에서 복원·렌더한 longform 1.8s, 126.7s 프레임)도 같이 봤다. 지금 화면은 "타이포 + 숫자 + 진행 막대"만 있고 그림이 0장이다. 이 문서의 목표는 **그 화면에 일러스트 슬롯 1개를 얹는 규칙**을 정하는 것이지 화면 전체를 갈아엎는 게 아니다.

## 1. 15장 카드 (DAY1 레퍼런스 카드 양식)

DAY1 `[56:52]`의 방식대로 "무엇이 보이나 → 왜 그렇게 했나(추정) → 내 영상에서 어디에 쓰나"로 적었다. "추정"은 작가 의도를 내가 짐작한 것이다.

### 01 — "NOT FASHION DAY" 포스터 (1200×1643)
- **보이는 것**: 따뜻한 회백색 종이 바탕에 미세한 노이즈 질감. 좌상단에 코발트블루 세리프 대문자 제목 3줄("NOT / FASHION / DAY"), 제목 뒤에 주황색 유기적 얼룩(blob)이 한 장 깔림. 제목 아래 주황 필기체 소제목 "simple days are better days". 우상단에 세리프 "01". 좌하단에 작은 로고 + 자간 넓은 세리프 소문 "LINE FESTIVAL". 인물: 쪼그려 앉은 남자. 검정 스웨터는 **질감 있는 검정 면**, 윤곽선은 **파란 굵은 선**, 손·얼굴·신발끈은 **주황 선**. 바지는 종이색 그대로(채우지 않음). 면과 선이 정확히 맞지 않고 어긋나 있다(오프레지스터).
- **추정 이유**: 세리프 제목 + 필기체 + 번호 = 잡지·페스티벌 포스터 문법. 선 색(파랑)과 면 색(검정/주황)을 분리해 "인쇄 판이 어긋난" 리소 느낌을 냄. 강조색 주황은 얼룩·소제목·피부선 세 곳에만 써서 시선 동선을 만든다.
- **내 영상에**: **에피소드 타이틀 카드(scene-01 phase 1)의 레이아웃 원형.** 제목(세리프 or 800 굵기) + 뒤에 강조색 얼룩 + 우상단 회차 번호 + 하단 채널명. 당신 화면의 "AI UPDATE / OPUS 5.5 / 01" 크롬과 이미 같은 구조다.

### 02 — 의자에 앉아 음료 마시는 남자 (736×920)
- **보이는 것**: 순백에 가까운 바탕. 파란 굵은 마커 선(둥근 끝), 주황 후드는 **윤곽선 없는 평면 색면**이 파란 선 밑에 깔려 있고 선과 어긋남. 운동화에 분홍 낙서 3개. 모자 파랑 면, 콧수염·안경 검정. 좌상단 손글씨 서명.
- **추정 이유**: 선 1색 + 면 1색 + 악센트 1색 = 3도 인쇄 규칙. 분홍은 신발에만 써서 "포인트"를 만든다. 얼굴을 거의 안 그리고(눈은 안경, 코는 삼각) 실루엣과 옷 색으로 인물을 만든다.
- **내 영상에**: **"인물 1명 + 소품 1개" 장면의 원형.** 당신 대본에 "사용자가 ~한다"가 나올 때 이 정도 밀도면 충분하다. 단 분홍은 4번째 색이므로 당신 팔레트에선 뺀다.

### 03 — 신문 읽는 여자 스티커 (480×640)
- **보이는 것**: 남색 모노라인, 굵은 노란 스티커 테두리(다이컷 후광), 체크 바지(격자 선), 흰 운동화 + 주황 끈, 신문 안에 작은 주황 로고. 배경 없음(투명·흰색).
- **추정 이유**: 스티커 = 화면에 "붙인 것"처럼 보이게 하는 장치. 노란 테두리가 배경과 분리해 준다. 체크 패턴은 면을 채우지 않고 선으로 질감을 만드는 법.
- **내 영상에**: **일러스트를 종이 위에 "붙이는" 연출의 근거.** 당신 `.paper` 카드 규칙(#FFFCF5, 2px #B5BAAB)과 결합하면 "스티커 놓기" 등장 애니메이션이 자연스럽다. 노란 테두리 대신 종이색(#F4F0E7) 두꺼운 외곽선 + 얕은 그림자로 치환.

### 04 — "MyCoffee" 남색 포스터 (736×920)
- **보이는 것**: 짙은 남색 바탕 전면. 가운데 크림색 다이컷 스티커, 그 안에 남색 스케치(선이 거칠고 여러 번 겹침) — 번 머리·선글라스·놀란 입·넘치는 커피컵. 스티커 곡선을 따라 필기체 "Surprise me, coffee!". 타이포 그리드: 좌상 "Sip the Energy." / 우상 "Own the Day." (자간 넓은 소문), 좌측 타자기체 인용 "You can do it" - Coffee, 우측 굵은 산세리프 "01. MyCoffee", 하단 커피 아이콘 + 가로줄 + "My coffee is strong, so am I".
- **추정 이유**: 반전(어두운 배경 + 밝은 스티커)으로 시선을 스티커에 고정. 코너 라벨 4개 + 번호 + 하단 줄은 "시리즈물"이라는 신호. 선을 거칠게 여러 번 그은 것은 "손으로 그렸다"는 증거를 남기는 것.
- **내 영상에**: **반전 장면(어두운 바탕) 1종을 허용할지 결정할 근거.** 당신 design.md는 밝은 종이 1종이다. 롱폼 6장면 중 "주의/경고" 성격의 장면 하나(예: scene-05 "과대 해석 주의")에만 잉크색 #222820 바탕 + 종이색 스티커로 반전을 쓰는 선택지가 있다. 코너 라벨 구조는 당신 chrome과 동일.

### 05 — BRIO 카페 스티커 시트 (1200×1696)
- **보이는 것**: 한 색(파랑)만 쓴 모노라인 인물 7개 + 말풍선 스티커 3개("TAKE YOUR TIME!", "BUT FIRST, COFFEE!", "BREW-TIFUL MORNINGS START HERE") + 크루아상 + 로고 락업. 흰 다이컷 테두리 + 연회색 그림자. 머리·바지만 파랑 면으로 채움, 나머지 비움. 얼굴은 점 눈 + 작은 코 + 홍조 점.
- **추정 이유**: 브랜드 굿즈용 부품 세트. 같은 선 굵기, 같은 색, 같은 얼굴 문법으로 그려 어떤 조합으로 배치해도 한 세트로 보이게 함. 말풍선은 굵은 기하 산세리프 대문자로 "그림 안의 텍스트"가 됨.
- **내 영상에**: **가장 중요한 카드.** DAY2 `[50:33]`의 "곰 48장 자산 분류"가 바로 이것이다. 당신이 만들 것은 "장면마다 새 그림"이 아니라 **부품 세트(인물 포즈 6~8개 + 소품 10~15개 + 말풍선 2~3종)**이고, 이 시트가 그 완성 형태다. 부품은 SVG 코드로 만들어 `assets/parts/`에 둔다(02 문서의 B안).

### 06 — 고양이 흑백 스티커 시트 1 (854×1200)
- **보이는 것**: 검정 굵은 마커 선, 흰 바탕. 고양이 5마리(얼룩은 검정 면), 화분, 음악 플레이어 UI를 그림으로 그린 것, 토스트, 카메라, 손글씨 캡션("take it", "cat music", "cat toast", "take pictures of cat"). 반짝임 표시(짧은 선 3개), 물음표.
- **추정 이유**: 캡션을 손글씨로 그림 옆에 붙여 "그림+말"을 한 덩어리로 만든다. UI(플레이어)를 그림으로 그리는 것은 화면 속 화면을 부드럽게 만드는 방법.
- **내 영상에**: **"소프트웨어 화면"을 그릴 때의 규칙.** 당신 채널은 AI 도구 얘기라 채팅창·설정창·가격표가 자주 나온다. 스크린샷 대신 이 방식(굵은 선으로 창 틀 + 버튼 3개 + 손글씨 라벨)으로 그리면 저작권·해상도 문제가 없고 스타일이 유지된다. 반짝임 선 3개는 "숫자 팝인" 뒤에 붙일 가장 싼 모션 마크.

### 07 — 고양이 흑백 스티커 시트 2 (913×1280)
- **보이는 것**: 06과 같은 손. 케이크 위 고양이, "TO DO" 종이가방(웃는 얼굴), 꽃다발, 헤드폰, 껴안은 고양이 둘, 자는 고양이("zzz"), 젖소무늬 컵, 양말. 움직임 표시(반짝임, 짧은 선, 김).
- **추정 이유**: 사물에 얼굴을 붙여(종이가방) 의인화. 검정 면은 고양이 얼룩·양말 발꿈치·컵 무늬처럼 **패턴**으로만 쓰고 큰 면을 채우지 않는다.
- **내 영상에**: **소품 사전.** 헤드폰·컵·가방·꽃은 "작업, 휴식, 비용, 보상" 같은 추상 개념의 대체물로 쓸 수 있다. 예: "월 구독료" = 지갑/가방, "실행 비용" = 계량컵. 이런 **개념↔소품 대응표**를 design.md에 두면 AI가 visuals.json을 쓸 때 소품 선택이 안정된다.

## 2. 공통 문법 — 본 10장에서 반복되는 것

| # | 문법 | 근거 장 | 예외 |
|---|---|---|---|
| G1 | **선은 한 장 안에서 굵기가 균일**하고 끝이 둥글다. 굵기는 두 계열: 굵은 마커(01·02·03·05·06·07) / 가는 펜(13·15) | 10장 중 9장 | 08만 붓선(굵기 변화) |

## 4. 코드로 옮기는 법 (HyperFrames 기준)

당신 build_video.py는 이미 장면 HTML을 Python f-string으로 찍어낸다. 일러스트는 **그 HTML 안에 인라인 SVG 1덩어리**를 추가하는 것이므로 구조 변경이 없다.

### 4-1. 부품 파일 (assets/parts/*.svg)

한 부품 = SVG 조각 1개. 스타일은 부품 안에 두지 않고 부모 CSS가 준다(색·굵기를 장면에서 바꿀 수 있게). Monoline 스킬 9장 함정대로 `<g id><g transform>…</g></g>` 이중 그룹.

```svg
<!-- assets/parts/cup.svg  (viewBox 0 0 200 200, mono 9px 기준으로 그린다) -->
<g id="cup" class="part">
  <g class="xf">
    <path class="ink w-mono" d="M40 70 H150 L140 170 Q100 182 60 170 Z"/>
    <path class="ink w-mono" d="M150 90 Q195 95 185 130 Q178 150 148 148"/>
    <path class="fill-accent off" d="M46 78 H144 L135 164 Q100 175 65 164 Z"/>
    <path class="ink w-mono mark steam" d="M80 50 Q70 35 80 20 M110 50 Q100 35 110 20"/>
  </g>
</g>
```

부모 CSS(장면 `<style>`에 build_video.py가 넣는다):

```css
.part .ink{fill:none;stroke:#222820;stroke-linecap:round;stroke-linejoin:round;vector-effect:non-scaling-stroke}
.part .w-hair{stroke-width:5}.part .w-mono{stroke-width:9}.part .w-emph{stroke-width:14}
.part .fill-ink{fill:#222820;stroke:none}
.part .fill-accent{fill:#AB411F;stroke:none}

.sticker{paint-order:stroke;filter:drop-shadow(0 6px 0 rgba(83,96,82,.18))}
.sticker .ink{stroke:#F4F0E7;stroke-width:22}       /* 후광용 복제 레이어에만 적용 */
```

후광은 같은 부품을 두 번 그린다: 아래에 `.sticker` 클래스로(종이색 굵은 선), 위에 원래대로. `<use href="#cup">`로 복제하면 CSS 선택자가 `<use>` 안으로 못 들어가므로(07 문서 2절) 후광 레이어는 `stroke:currentColor` + 부모 `color:#F4F0E7`로 준다.

### 4-2. build_video.py `content()`에 추가할 슬롯

```python
def illustration(ill, uid):
    if not ill: return ""
    parts = "".join(
        f'<g class="part-slot" transform="translate({p["x"]},{p["y"]}) scale({p.get("scale",1)})">'
        f'{PARTS[p["id"]]}</g>'
        for p in ill["parts"])
    return (f'<svg class="ill ill-{ill.get("enter","draw")}" id="ill-{uid}" '
            f'viewBox="0 0 1920 1080" width="1920" height="1080" aria-hidden="true">{parts}</svg>')
```

`PARTS`는 `assets/parts/*.svg`를 빌드 시 읽어 문자열로 든 dict. 부품 안의 `id`는 `uid`를 붙여 중복을 피한다(같은 컵이 두 장면에 나오면 id가 충돌한다).

### 4-3. GSAP 타임라인 (장면 `<script>`에 추가)

draw-on은 각 path의 길이가 필요하므로 타임라인을 만들기 전에 한 번 잰다. HyperFrames는 `window.__timelines[cid]`에 paused 타임라인만 있으면 되므로 아래를 기존 `tl` 뒤에 붙인다.

```js
document.querySelectorAll('#ill-{uid} .ink').forEach(p=>{
  const L=p.getTotalLength(); p.style.strokeDasharray=L; p.style.strokeDashoffset=L;
});
tl.to('#ill-{uid} .ink',{strokeDashoffset:0,duration:0.7,ease:'none',stagger:0.05},{ill_start});
tl.fromTo('#ill-{uid} .fill-ink, #ill-{uid} .fill-accent',{opacity:0},{opacity:1,duration:0.001},{ill_start}+0.82);
tl.fromTo('#ill-{uid} .mark',{opacity:0},{opacity:1,duration:0.1,repeat:3,yoyo:true},{ill_start}+1.1);
```

주의 세 가지.
- `strokeDashoffset`을 GSAP이 만지면 `vector-effect: non-scaling-stroke`와 함께 써도 문제없다. 하지만 `transform`을 GSAP으로 만지면 SVG `transform` 속성을 덮어쓴다(Monoline 함정) → 위치는 항상 바깥 `<g class="part-slot" transform=…>`에만 두고, 애니메이션은 안쪽 요소의 `opacity`·`strokeDashoffset`·CSS 변수만 만진다.
- `getTotalLength()`는 폰트와 무관하므로 렌더 결정성에 영향이 없다. 단 `<template>` 안에 있는 SVG는 DOM에 붙기 전엔 길이를 못 잰다 → HyperFrames가 템플릿을 마운트한 뒤 스크립트가 실행되는지 `check`로 확인하고, 안 되면 빌드 시 Python에서 길이를 미리 계산해(svgpathtools) `data-len` 속성으로 박는다.
- 숫자 팝인(`number-pop-in`)과 draw-on 시작 시각은 0.4s 이상 띄운다(7-3 예산).

### 4-4. 검사 스크립트 (7-4 통과조건을 코드로)

`tools/check_video.py`에 추가할 검사 3개(정규식으로 충분):
1. 장면 HTML마다 `class="ill"` 개수 ≤ 1
2. `fill="`/`fill:` 값이 허용 집합 밖이면 실패
3. `stroke-width` 값이 {5,9,14,22} 밖이면 실패

그 다음 `npx hyperframes check`(layout·contrast) → `snapshot --at <각 장면 중간>`으로 사람 확인.

### 4-5. Remotion으로 할 경우

같은 SVG 부품을 `<svg>` JSX로 붙이고 draw-on은 `interpolate(frame, [s, s+21], [L, 0])`을 `strokeDashoffset`에 준다. 부품 자체는 동일하게 재사용된다. 즉 **부품 세트는 도구와 무관한 자산**이다. 05 문서의 결론(HyperFrames 유지)과 무관하게 지금 부품을 만들어도 손해가 없다.
