# DAY1 상세 분석 — "레퍼런스를 뜯어서 편집 규칙으로 옮기기"

- 원영상: https://www.youtube.com/watch?v=MHBB9UJOzMc (2:07:09, Vestment Jun, 2026-08-11 업로드, 미등록)
- 읽은 자료: 한국어 자동 자막 전문(3,028 세그먼트, 0:00~2:07:09 전 구간). 화면(프레임)은 이 환경에서 YouTube 다운로드가 프록시 403으로 차단되어 직접 보지 못했다. 화면 묘사는 강사의 발화에 근거한 것이며, 발화만으로 확인이 안 되는 것은 "미확인"으로 적었다.
- 표기: `[mm:ss]`는 자막 세그먼트 시작 시각. 인용은 자동 자막이라 오인식("컵 편집"→컷 편집, "주민"→줌인, "기터브"→GitHub, "페이블"→Fable, "오프스"→Opus)을 바로잡아 적었다.

## 0. 한 줄 요약

DAY1은 도구 설치 강의가 아니라 **"내가 좋다고 느낀 편집을 AI가 재현 가능한 규칙으로 바꾸는 법"** 강의다. 핵심 주장은 세 가지다.

1. 레퍼런스 영상을 **그대로 던지지 말고, 내가 꽂힌 구간(시간+초)과 왜 좋은지(맥락)를 직접 적어서** 분석시켜라. `[63:31]`~`[64:13]`
2. 분석 결과의 **숫자(3초 전환, 18글자)를 베끼지 말고 의도를 규칙화**하라. `[66:45]`~`[67:09]`
3. 만족한 결과가 나오면 그 대화를 **스킬(시스템)로 승격**한다. 그 전까지는 계속 "깎는다". `[31:00]` 전후, `[126:17]`

당신(hyjune) 프로젝트 기준으로 보면, 이 강의의 "레퍼런스 분석 → 규칙 → HyperFrames로 구현"이 바로 `ai-news-video/design.md`와 `tools/build_video.py`가 하는 일이다. 즉 이미 3주차 수준(스킬화)까지 와 있고, 지금 필요한 것은 DAY1의 "레퍼런스 분해 정밀도"를 일러스트 레퍼런스 15장에 적용하는 것이다.

### 2-1. [04:10–07:30] 강사가 보여준 결과물 3종 — 목표 스타일의 좌표

- `[04:18]` "시네마틱한 느낌": 대본("AI가 발전했는데도 대부분은 편집 프로그램 앞에서 에너지를 뺏기고 있습니다")에 맞춘 효과 위주 영상. 강사 본인은 "이런 편집 효과들 개인이 절대 못 만든다 … AI가 만들어 준다"고 말한다.
- `[05:09]` "엄청 깔끔한 스타일": 같은 대본을 정돈된 텍스트/도형으로. 여기서 나온 중요한 문장 — **"절대 하지 말아야 할 행동 … 내가 구현하고 싶은 이미지에 대해서 주저리주저리 설명하는 것"**. 즉 말로 그림을 설명하지 말고 레퍼런스를 줘라.
- `[05:56]` "제일 애용하는 효과": 화면 녹화 위에서 설명 중인 구간을 줌인하거나 테두리를 쳐 주는 효과. "이런 작업들 프레임 하나하나 캡처하고 줌인 효과 넣고 하는데 시간 진짜 많이 걸리는데 저것도 다 자동화" `[06:20]`. 입력은 **컷편집된 영상 하나**.
- `[07:00]` 강사가 개발 중인 편집기("동컷", 자막에는 "돈"): 전사 → 삭제 → 구간에 효과 삽입. "8월 내로 프리미어 프로를 삭제하려고" `[07:30]`.

**당신에게 적용:** 세 유형 중 당신의 목표(일러스트 레퍼런스 스타일의 AI 뉴스 해설)는 두 번째 "깔끔한 설명형"의 확장판이다. 세 번째(화면 줌인)는 실제 서비스 화면을 넣을 때만 쓴다(AGENTS.md의 "없는 UI를 실제 시연처럼 표현하지 않는다"와도 맞다). 첫 번째(시네마틱)는 당신 채널 톤과 맞지 않으니 버려도 된다.

### 2-2. [07:30–13:00] 시간 절약 주장과 사업 사례 — 걸러서 들을 부분

- `[08:00]` 프리미어에서 이미지 한 장 배치에 3분, 10~15분 영상에 이미지 배치만 1~2시간. 편집 반나절 → 컷편집만 하고 AI에 맡기면 약 3시간.
- `[09:19]` 윤자동(토스 출신) 사례: 라이브 1편 → 롱폼 6개 + 숏폼 십수 개, 하루 만에 17만 1천 원 매출. `[11:08]` "편집 외주 시장 200억~600억".
- `[11:26]` 뉴스레터 서비스, 크리에이터 커뮤니티, `[12:10]` 유치원 채용 플랫폼("시장 10~20억, 점유율 30~40% 먹을 수 있겠다").

**가감없는 평가:** 시간 절감은 강사 본인의 체감이고, 시장 규모·점유율·매출은 근거가 제시되지 않았다. 동기부여용 이야기다. 당신의 롱폼 3~5분 파이프라인에서 실제로 시간이 어디에 드는지는 이번에 확인한 사실로 대체하자: 대본 → TTS → 정렬 → 빌드 → **check 실패**에서 멈춰 있다(05 문서 참고). 시간 절감 계산은 그 병목이 풀린 뒤에 해야 의미가 있다.

## 3. DAY1에서 "그대로 따르지 말 것"

1. **스타 수 = 사용자 수** 환산, **시장 규모/매출** 수치: 근거 없음.
2. **권한 무시 기본값**: 강사도 위험을 인정. 폴더 격리 없이 쓰지 말 것.
3. **한글 경로 금지**: 당신 환경에서는 문제가 아니었다. 문제가 나는 도구에서만 영문 경로.
4. **"토큰 다 쓰기"를 성과로**: 사용량은 비용이지 성과가 아니다. 당신 AGENTS.md의 "검증 전 complete 표시 금지"가 더 좋은 기준이다.
5. **인스타 다운로드 사이트** 추천: 권리·안전 미확인.

## 4. DAY1에서 당신 프로젝트에 바로 넣을 것

1. **레퍼런스 카드 양식**(구간/무엇/언제/어떻게/왜/내 영상에 맞는가)을 `episodes/<ep>/reference.md`로 추가하고, 일러스트 15장을 이 양식으로 적는다(04 문서에 초안 있음).
2. **"디자인 소스는 있어야 한다"**를 받아들여 `assets/illustrations/`를 만들고, 장면 유형별로 필요한 일러스트 부품 목록을 먼저 정한다(캐릭터 1, 소품 6~10, 배경 질감 1, 스티커/도형 5).
3. **의도 규칙화**: "숫자가 크면 팝인"이 아니라 "시청자가 계산해야 하는 수치가 나올 때만 hero 레이아웃, 그 외에는 statement". 이미 visuals.json의 layout 선택이 그 역할이다. 선택 기준을 design.md에 문장으로 적어 두면 다음 에피소드에서 AI가 같은 판단을 한다.
4. **분석은 사람이**: 새 레퍼런스 영상이 생기면 먼저 당신이 5~15초를 골라 효과를 세고 적은 뒤에 AI에 준다.
