# 적용 로드맵 — 세 강의를 당신의 ai-news-video 파이프라인에 넣는 순서

이 문서는 강의 요약이 아니라 **실행 순서**다. 01~03(강의 분석), 04(스타일), 05(도구 검증)의 결론을 한 줄기로 묶었다. 각 단계에 "끝났다"를 판정할 조건을 붙였다. 이 조건은 강의의 "AI가 완료했다고 말했다"(DAY3 `[36:35]`)가 아니라 실제 파일 검증이다.

| 항목 | 상태 | 근거 |

## 1. 단계별 로드맵

### 1단계 — 지금 있는 것부터 MP4로 (스타일 변경 없이)

목표: 오퍼스 5.5 롱폼 1편 + 숏폼 3편을 현재 design.md 그대로 렌더해 재생 가능한 MP4를 만든다.

1. 05 문서의 check 오류 원인과 패치를 build_video.py에 적용한다.
2. `python tools/build_video.py episodes/2026-09-22-opus-5-5` → 각 프로젝트에서 `npx hyperframes@0.8.79 check` 0 errors.
3. `npx hyperframes snapshot --at <각 phase 중간 시각>`(proof-times.json이 이미 이 용도) → 장면당 1장 눈으로 확인.
4. `npm run render` → `ffprobe`로 길이(282.52±0.1s)·해상도·오디오 스트림 확인.
5. Google 목소리 승인(README "첫 Google 샘플 평가 후 전체 생성") — 아직 미승인이면 여기서 결정.

**완료 조건:** 롱폼·숏폼 4개 MP4가 있고, check 0 errors, 자막이 음성과 맞는지 3곳(시작/중간/끝) 청취 확인, AGENTS.md 검증 항목 통과.
**강의 대응:** DAY2 "한 편의 완벽한 영상" 숙제. DAY2 `[37:39]` "수정할 때 집중" — 렌더 기다리며 딴 일 하다 넘기지 말 것.

### 2단계 — 레퍼런스 분해 (사람이 먼저)

목표: 일러스트 레퍼런스 15장에서 **스타일 문법**을 뽑아 design.md에 "일러스트 층"을 추가한다. 04 문서에 초안이 있다.

1. 04 문서의 토큰 표를 읽고 동의/수정한다(특히 라인 캡 round vs butt, 팔레트 2색 vs 3색).
2. 강조색 의미 2개 고정(Monoline 5-2): ①수치 ②활용 제안 표지.
3. 레퍼런스 카드(DAY1 양식)를 `episodes/_reference/illustration-refs.md`로 저장한다. 04 문서의 표를 그대로 옮기면 된다.

**완료 조건:** design.md에 "일러스트" 절이 생기고, 원칙(문장)/고정값(수치)/통과조건(검수)이 3층으로 분리되어 있다.
**강의 대응:** DAY1 `[59:19]` "분석은 사람이", DAY3 `[30:27]` 3층 분리.

### 3단계 — 일러스트 부품 세트 만들기 (여기가 새 작업)

목표: 매 에피소드마다 그림을 새로 그리지 않도록 **재사용 부품**을 만든다.

| 부품 | 형식 | 수량 | 만드는 법 |
|---|---|---|---|
| 캐릭터 1명(정면/측면/앉음/노트북/커피/생각) | 투명 PNG 2000px 또는 SVG | 6 포즈 | 이미지 생성(나노바나나/GPT)에 04 문서의 스타일 프롬프트 + "흰 배경, 검은 모노라인, 채색 없음" → 배경 제거 → 필요하면 벡터화 |
| 소품(노트북, 서류, 달력, 저울, 동전, 화살표, 말풍선, 커피잔, 시계, 체크박스) | SVG(코드) | 10 | Claude/Codex에 **한 개씩** SVG로 그리게 하고 라인 두께·캡을 CSS 클래스로 통일(Monoline 8장 CSS) |
| 종이 질감 | PNG 타일 512px | 1 | 생성 또는 CSS 노이즈(`feTurbulence`) — 05 문서 참고: 외부 URL 로드는 렌더 결정성을 깨니 로컬 파일로 |
| 스티커(원 강조, 밑줄, X, 별) | SVG | 5 | 코드 |

각 부품에 대해 `assets/illustrations/manifest.json`에 DAY2 곰 48장 분류법으로 적는다: 파일, 무엇, 어울리는 대사 유형, 텍스트 여백 위치, 비율, 출처/권리.

**완료 조건:** manifest에 20개 이상, 모두 같은 라인 두께·팔레트, `hyperframes check`에서 request_failed 0(모든 파일 로컬).
**강의 대응:** DAY1 `[22:11]` "디자인 소스는 있어야", DAY2 `[51:40]` "코드로 그리면 깨진다 → 이미지로", `[55:12]` 정리된 자산.

### 4단계 — 레이아웃에 일러스트 자리 만들기

build_video.py의 6개 레이아웃(hero/prices/split/steps/paper/equation/statement)에 **선택적 `illustration` 필드**를 추가한다. visuals.json 예:

```json
{ "at": "사십 퍼센트는", "layout": "hero", "title": "40% 저렴?", "big": "40", "unit": "%",
  "illustration": { "asset": "char-think", "side": "right", "motion": "draw" } }
```

- `side`: left/right/bottom(세로에서는 bottom 고정).
- `motion`: `draw`(stroke-dashoffset 15~30f) / `place`(손이 놓듯 위→아래 15f + 2% 오버슈트) / `none`.
- 규칙: 한 장면에 일러스트 1개, 텍스트와 같은 시각에 등장하지 않고 **핵심어 4프레임 전**에 완성(Monoline 5-9).

**완료 조건:** 6장면 중 3장면에 일러스트가 들어간 v2가 렌더되고, v1과 나란히 비교한 스냅샷이 있다.
**강의 대응:** DAY2 `[47:37]` 버전 보존, DAY1 `[66:45]` 숫자 베끼기 금지(모든 장면에 넣지 않는다).

### 5단계 — 피드백 라운드 (규칙을 고친다)

1. v2를 보고 DAY2 양식으로 피드백을 쓴다(아래 2절).
2. 매 피드백 뒤 "왜 그랬어?" → 원인이 visuals.json(장면 판단)인지, design.md(원칙)인지, build_video.py(코드)인지 분류.
3. 3회 반복 후 개선이 없으면 문제를 다시 정의한다(무한 루프 금지).

**완료 조건:** 변경 기록(changelog)에 "v2→v3: 규칙 X를 Y로, 이유 Z" 형식이 3건 이상.

### 6단계 — 새 에피소드로 재현 테스트 (스킬 검증)

GPT-6 Astra(주제선정.md 2순위)로 **새 세션·새 폴더**에서 처음부터. 막힌 지점을 AGENTS.md/design.md에 추가.

**완료 조건:** 사람이 개입한 횟수와 사유가 기록되어 있고, 2편째 총 작업 시간이 1편째보다 짧다(측정값).
**강의 대응:** DAY3 `[33:52]` 새 대화창, `[58:00]` 규칙 근거 5질문.

### 7단계 — 공개(선택)

GitHub 공개 전: API 키·채널 ID·이메일 grep, 폰트 라이선스(Pretendard OFL 포함 OK), 일러스트 부품 권리 확인.

## 2. 당신 프로젝트용 프롬프트 6개

강사 노션의 원문 프롬프트는 비공개라 복원하지 않았다. 아래는 세 강의의 원칙으로 **당신 파일 구조에 맞춰 새로 쓴 것**이다. 대괄호는 채운다.

### P1. 레퍼런스 스타일 분해 (DAY1 마스터 프롬프트의 당신판)

```
너는 에디토리얼 일러스트 아트디렉터이자 HyperFrames 개발자다.
목적: 아래 일러스트 15장의 "스타일 문법"을 우리 채널(공식 AI 발표를 정확히 읽어 주는 3~5분 해설, 페이스리스, 한국어)의
design.md에 추가할 규칙으로 옮긴다. 그림의 소재(커피, 패션, 인물 포즈)는 옮기지 않는다.
입력: assets/reference/illustration-refs/ (15장), design.md(현재 토큰)
내가 꽂힌 지점:
 - 01: 굵은 파랑 컨투어 + 주황 스팟 컬러 + 세리프 대제목 + 손글씨 액센트 + 종이 그레인. "정보 포스터" 구도가 좋다.
 - 02/13/15: 검은 모노라인 캐릭터, 채색 최소, 여백 많음. 우리 캐릭터를 이 문법으로 만들고 싶다.
 - [추가]
출력(파일로): design.md에 넣을 "일러스트" 절 초안 —
 1) 원칙 3문장 이내(긍정문), 2) 고정값(라인 두께 px 3단계, 캡/조인, 팔레트 HEX와 각 색의 의미, 종이 질감 불투명도, 오프레지스터 px),
 3) 통과 조건(자막 대비, 안전 여백, 한 장면 일러스트 1개), 4) 15장 각각에 대한 카드(무엇/왜 좋은지/옮길 규칙/옮기면 안 되는 고유 요소).
관찰과 추정을 구분하고, 확신이 낮은 값은 "시험값"이라고 표시해라. "3초마다", "18글자" 같은 사례 수치를 전체 규칙으로 만들지 마라.
```

### P2. 부품 SVG 한 개 만들기 (3단계)

```
design.md의 일러스트 절을 읽고, 소품 "[달력]"을 SVG 하나로 그려라.
조건: viewBox 0 0 400 400, 선은 class="mono"(stroke:currentColor; stroke-width:17; linecap:[round]; linejoin:[round]), 채움은 class="spot"(fill:var(--accent)) 한 군데만,
텍스트 없음, 그룹 구조는 <g id="..."><g transform="..."> 이중(GSAP가 transform을 덮어쓰지 않게), 드로잉 애니메이션용으로 path 3~6개로 분해.
저장: assets/illustrations/prop-calendar.svg. manifest.json에 항목 추가(무엇, 어울리는 대사 유형, 여백, 비율, 출처=직접 제작).
다른 소품과 선 두께가 같은지 확인하고, 렌더 없이 확인이 안 되는 것은 "미확인"이라고 적어라.
```

### P3. 장면에 일러스트 배치 (4단계, DAY2 곰 실습의 당신판)

```
episodes/[ep]/visuals.json의 각 phase에 대해 assets/illustrations/manifest.json에서 어울리는 부품을 고르되,
 - 한 phase에 최대 1개, 6장면 중 3~4장면에만. 숫자가 주인공인 hero에는 캐릭터를 넣지 않는다(숫자와 경쟁).
 - 고른 이유와 버린 후보의 이유를 phase마다 적어라. 없으면 "없음"이라고 적고 새로 만들 부품을 제안해라(만들지는 마라).
 - side/motion을 정하고, 등장 완성 시각은 해당 phase의 at 문구보다 4프레임 앞.
결과를 visuals.json에 "illustration" 필드로 써 넣고, 변경 전 파일은 visuals.v1.json으로 보존해라.
```

### P4. 피드백 (5단계, DAY2 `[38:42]`~`[40:29]` 양식)

```
대상: episodes/[ep]/longform/renders/final_v[NN].mp4
문제 시각: [mm:ss]~[mm:ss] (scene-[XX] phase [n])
관찰: [예: 캐릭터가 큰 숫자 40% 왼쪽에 있어서 시선이 둘로 갈린다]
왜 문제인지: [시청자는 이 순간 숫자를 읽어야 한다]
내 맥락: 나는 디자이너가 아니다. 규칙에 맞는 대안을 네가 골라라.
원하는 결과: [숫자가 먼저 읽히고 캐릭터는 보조]
요청: 이 결과가 나온 원인이 visuals.json 판단인지, design.md 규칙인지, build_video.py 코드인지 먼저 찾아 근거(파일·줄)를 보여라.
장면만 고칠 일인지 규칙을 고칠 일인지 구분해서 제안하고, 내가 고른 뒤에 그 구간만 다시 빌드해라. 다른 장면 스타일은 바꾸지 마라.
새 출력은 final_v[NN+1].mp4로 저장해 v[NN]과 비교할 수 있게 해라.
```

### P5. 규칙 근거 점검 (DAY3 `[58:00]` 5질문)

```
design.md와 AGENTS.md의 각 규칙에 대해 표로 답해라: 규칙 / 근거(어느 결과물·피드백에서 왔나) / 사실과 충돌하는 점 / 이번 에피소드 전용인지 공통인지 / 새 세션에서 읽어도 이해되는지 / 배포 시 민감정보 여부.
근거가 없는 규칙은 "가설"로 표시하고 삭제 후보로 올려라. 규칙을 고치지는 마라.
```

### P6. 새 에피소드 재현 (6단계, DAY3 `[33:52]`)

```
(새 폴더·새 세션에서) 이 저장소의 AGENTS.md, README.md, design.md, tools/ 만 읽고 시작해라. 이전 대화는 없다.
입력: episodes/2026-XX-gpt6-astra/sources.md (공식 링크 2개)
목표: 롱폼 1 + 숏폼 3을 built_pending_checks까지. 음성은 승인된 Google 목소리 [이름].
실행 중 (a) 지침만으로 된 것 (b) 추론이 필요했던 것 (c) 막혀서 나에게 물어야 했던 것 (d) check 결과를 나눠 보고해라.
(c)는 반드시 물어라. 추측으로 채우지 마라. complete라고 쓰려면 AGENTS.md의 검증 항목 근거를 붙여라.
```

## 3. 시간·비용을 재는 법 (강사의 "본전" 계산을 당신 수치로)

DAY2 `[09:06]` "3~4시간이면 만든다"는 강사 체감이다. 당신은 다음을 기록하면 된다.

| 에피소드 | 사람 시간(입력 정리+검수+수정) | 대기 시간(TTS/렌더) | API 비용 | check 실패 횟수 | 결과 |
|---|---|---|---|---|---|
| 오퍼스 5.5 (1편) | | | | 1+ | 미완 |
| GPT-6 Astra (2편) | | | | | |

2편이 1편보다 사람 시간이 줄지 않으면 부품 세트·규칙에 문제가 있는 것이다. 회수 편수 = 초기 구축 시간 ÷ 편당 절감 시간(04_선생님_실행가이드의 공식과 같다).
