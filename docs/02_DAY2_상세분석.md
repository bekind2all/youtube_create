# DAY2 상세 분석 — "결과물 무한 피드백: 장면이 아니라 규칙을 고친다"

- 원영상: https://www.youtube.com/watch?v=u-yclQubVHg (1:26:29, 2026-08-19 업로드, 미등록)
- 읽은 자료: 한국어 자동 자막 전문(2,120 세그먼트, 전 구간). 화면은 직접 보지 못했다(프록시 차단). `[mm:ss]`는 자막 시작 시각.

## 0. 한 줄 요약

DAY2의 주장은 하나다. **"결과가 마음에 안 들 때 그 장면만 고치면 1회용이고, 그 결과를 만든 규칙(지침)의 뿌리를 찾아 고쳐야 시스템이 된다."** 그리고 그 과정에서 생기는 **금지 목록 누적을 경계**하고, 소스(이미지·로고·음악)를 "AI가 용도를 판단할 수 있는 상태"로 정리하라고 한다.

당신 프로젝트 기준: `design.md`(긍정 원칙 위주로 잘 쓰여 있다), `visuals.json`(장면·레이아웃 판단), `build_video.py`(규칙을 코드로 고정)가 정확히 이 구조다. DAY2에서 가져올 것은 (1) 피드백 문장 양식, (2) 회색 막대 사례가 경고하는 "금지 규칙 누적", (3) 이미지 자산 목록화 방법이다.

## 2. 구간별 상세

### 2-1. [00:00–02:25] "편집 수준이 높지 않은데 100만"

`[00:19]` 지식브런치: "편집은 진짜 뭐가 없어요. 영상 소스를 계속 갖다 붙인 것 … 자료 조사는 AI 시킬 수 있는데 대본을 집중할 수 있게 구성하는 게 능력". `[01:00]` "이런 거는 자동화할 수 있거든요."

**적용:** 당신의 채널 컨셉("공식 발표의 숫자를 읽고 내 업무에 적용할 판단 기준으로 옮기는 편집 노트")은 정확히 이 유형이다. 일러스트 스타일은 "보기 좋게" 만드는 장치이지, 채널의 힘은 사실표와 해석에서 나온다. 스타일에 시간을 쓰되 **첫 에피소드에서 스타일 완성도 때문에 발행이 밀리면 안 된다.** 현재 상태(check 실패로 MP4 미완성)를 보면 이 경고가 유효하다.

### 2-2. [02:25–05:30] 복습과 첫 번째 경고

- `[02:25]` 오늘 주제 "결과물 무한 피드백".
- `[02:50]` "결과물이 다 똑같아요 … 모두가 똑같은 레퍼런스로 똑같은 자기계발 음성을 사용". 제출방에 강사 레퍼런스 결과물을 공유("색깔 바꾸든 뭘 하든 상관없다").
- `[03:41]` **"피드백 과정에서 '이거 하지 마, 저거 하지 마, 이건 싫어' … 이 모든 금지 항목들이 지침으로 스킬로 쌓이게 되면 안 됩니다. AI는 하지 말라는 말 100줄보다 잘하게 만들어 주는 좋은 한두 줄에 훨씬 잘 움직인다."**
- `[04:50]`~`[05:07]` 1주차 복습: 1) 찾는다 2) 목적을 주고 뜯어보게 만든다 3) 깎는다(이번 주).

**적용:** 당신 design.md는 이미 대부분 긍정문이다. 유일한 금지문은 "정보와 관련 없는 인물·AI 로봇·가짜 서비스 UI는 넣지 않는다"인데, 이건 강사도 인정하는 "반드시 지켜야 할 제약"(DAY3 `[30:27]`)에 해당하니 유지해도 된다. 앞으로 피드백을 쌓을 때 "~하지 마"가 5개를 넘으면 그 공통점을 한 문장의 원칙으로 바꾸는 습관을 들이면 된다.

### 2-3. [05:30–11:50] 레퍼런스가 중요한 이유

- `[05:26]` 채팅 답변 정리: "검증된 거라 리스크가 적다, 창작은 불가능하다, 이미 검증됐다."
- `[07:15]` 커뮤니티 홈페이지: "디자이너 두 명이랑 두세 달 걸려 만든 걸 … 나는 해킹해서 바로 만들 수 있다 … 디자이너 월급 200~300만 원 아끼고". `[08:01]` 카카오톡 홈페이지도 뜯어볼 수 있다.
- `[08:40]` **뜯어보게 할 때: "그냥 뜯어봐"가 아니라 "내가 왜 좋다고 느꼈는지 이유 + 목적(디자인 감각을 해킹하고 싶다)"까지.**
- `[09:06]` 템플릿 하나 만드는 데 처음 3~4일 → 10시간 → 3~4시간. "영상 세 편만 뽑으면 본전".

**가감없는 평가:** "타인 디자인을 해킹해 그대로 쓴다"는 표현은 구조·원리 참고까지는 맞지만, 실제 에셋(일러스트·폰트·사진)을 가져다 쓰는 것과는 구분해야 한다. 당신의 일러스트 레퍼런스 15장도 마찬가지다: **선 굵기·팔레트·구도 문법은 참고하되, 그림 자체를 트레이싱하거나 그대로 넣지 않는다.** 04 문서의 스타일 표는 그 경계를 지켜서 작성했다.

### 2-4. [11:50–24:40] 전문 용어와 용어 추출 실습

- `[11:56]` "잘하는 사람들은 이 전문 용어를 확실히 많이 압니다." `[12:06]` 승용 님(가스켓 제조업 영업직, 코딩 지식 없음)의 태극기 영상: "복스(Vox) 카드 기법", "콜라주 스타일", "푸티지 효과", "페이지 넘기기". 강사가 그 키워드로 "콜라주 복스 스타일"을 재현 `[14:20]`.
- `[16:14]` 상세페이지 스킬 시연 후 `[17:26]` 프롬프트: **"내가 외주 맡길 건데 무시당하기 싫다 … 용어 정도는 알고 의뢰하고 싶다. 이 상세페이지를 구성하는 용어를 알려 줘."**
- `[20:02]` 실습: 레퍼런스 영상 4:42~4:49 구간을 **watch 스킬**로 분석 → 용어 목록: 뉴스형 모션그래픽, 인포테인먼트 편집, 키네틱 타이포그래피, 지오메트릭 모션 요소, Mogrt. `[22:16]` 키네틱 타이포그래피 설명 요청 → "글자가 아래에서 위로 톡 올라오고, 중요한 단어만 크게, 한 글자씩 차르르, 핵심어에 색이 확 바뀌는 자막 연출".
- `[49:01]` 수강생들이 올린 용어: 플랫 디자인(그림자·입체감·그라디언트 없는 평면 그래픽), 컷 콜라주(사진 위에 오려 붙인 듯한 도형), 로어 서드(화면 아래 이름표), 듀오톤(흑백을 두 색으로).

**적용 — 당신의 일러스트 레퍼런스를 설명하는 용어(04 문서에서 확정):** 모노라인/굵은 컨투어 라인 드로잉, 리소그래프(리소) 인쇄 질감, 오프-레지스터(색 어긋남), 2~3색 스팟 컬러 팔레트, 플랫 컬러 블록, 종이 그레인/노이즈, 세리프 디스플레이 타이포 + 손글씨 액센트, 에디토리얼 포스터 레이아웃. 이 용어들을 프롬프트에 넣으면 "따뜻한 느낌으로"보다 훨씬 재현율이 높다.

### 2-5. [24:40–37:40] 회색 막대 사례 — 이 강의의 심장

- `[25:15]` 상황: 대사 100줄짜리 장면에서 AI가 계속 "회색 막대"로만 시각화. "추상적이다 … 직관적이지 않다."
- `[27:10]` "왜 효과를 넣는가? … 직관성을 위해서, 설명을 더 쉽게 이해할 수 있게 시각적인 요소를 넣는 것뿐."
- `[28:30]` 강사가 "너무 대충 일하는 것 같다, 직관적으로 하자"고 하자 AI가 지침을 **"막대 효과는 추상적이니 되도록 쓰지 말고 실제 문구를 넣어라"**로 수정.
- `[29:20]` 문제 제기: "막대 효과가 필요할 때가 있을 거잖아요 … 보라색 쓰지 마, 주황색 쓰지 마 … 다 쌓이면 단편적인 영상이 나온다." `[30:56]` **라면 비유**: "스프 두 개는 넣어야지"라고 하면 AI는 "라면은 무조건 스프 두 개"로 일반화한다.
- `[31:48]` 해법: **"근본적인 문제를 찾아라"** — "네가 수정한 내용은 너무 단편적이야. 어떤 지침 때문에 이렇게 만들었는지 봐라." `[32:20]` 지침서는 `style_rules.md`. `[33:30]` 실제 원인: "표현할 게 많을 때는 회색 바로 간단하게 설명한다"는 규칙이 들어 있었다.
- `[34:26]` "1회용이면 결과만 고치면 돼요. 근데 우리는 계속 사용할 시스템을 만들 거기 때문에 뿌리를 찾아서 고치는 게 가장 중요."
- `[35:46]` 카페 알바 매뉴얼 비유: "우유 150, 파우더 두 스푼"처럼 되는 것만 적어라. 금지문이 많으면 생각하는 시간이 늘고 성능이 떨어진다. "이건 정답이 아닐 수 있다 … 개발자들도 본질적인 방법은 맞다고 했다."
- `[37:39]` **"수정할 때는 집중하세요. 기다리다 딴 거 하다가 '잘했겠지' 하고 넘기면 돌이킬 수 없다."**

**적용 (구체적으로):** 당신 파이프라인에서 "회색 막대"에 해당하는 것은 `visuals.json`의 `statement` 레이아웃(알약형 pill 나열)이다. 6개 장면 중 3개가 statement이고 pill 텍스트가 4~8자 짧은 명사구다. 내레이션이 길고 설명이 많은 장면(03, 05)에서 pill만 나열되면 회색 막대와 같은 단조로움이 생길 위험이 있다. 고칠 때 "pill 쓰지 마"가 아니라 **"한 장면에서 내레이션이 30초를 넘으면 phase를 2개 이상으로 나누고, 두 번째 phase부터는 다른 레이아웃(paper/equation/hero)을 쓴다"**처럼 조건부 규칙으로 design.md에 적는 게 DAY2식 해법이다. (현재 build_video.py는 phase 앵커를 `at` 문구로 잡으므로 이 규칙은 코드 수정 없이 visuals.json 작성 규칙으로 넣을 수 있다.)

### 2-6. [37:40–50:30] 실제 피드백 시연

- `[38:42]` 3초 지점: "흰색 배경 안에 커피 한 잔과 아이콘 … 흰 배경이 세련미가 떨어져 … 질감이나 처리가 되면 좋겠어. **맥락: 내가 영상 편집자가 아니라 미감이 떨어져, 초보자야, 네가 적절한 효과를 찾아줬으면.**"
- `[39:54]` 12초 지점: "'꼬박 쓴 시간' 대사에 저 효과는 어울리지도 않고 직관적인 설명이 안 돼 … 왜 그런 건지 찾고 대안을 제시해 줘."
- `[40:29]` 마무리 문장: **"이게 왜 이렇게 나왔는지 알려 줘. 규칙을 근본적으로 고치고 그 부분을 다시 구현해 줘. 이렇게 가야 다음에 시행착오가 안 생기니까."** 대안: "규칙에서 근본 이유를 찾고 나에게 제안해 줘 → 내가 고른 뒤 다시 구현".
- `[46:30]` 결과: 흰 배경 → 다른 색 + 그림자, 12초 → 화면 추가 자체를 안 함("훨씬 깔끔"). AI 응답에 "배경은 평면으로 잘못 일반화했다" 같은 자기 진단.
- `[47:37]` **사고: "video.mp4 파일을 그대로 덮어씌운 것 같아요 … 기존 결과물을 못 보고 그다음 결과물만 확인"** → 버전 파일명 필요.

**적용:**
1. 피드백 문장 양식 = `시각 + 관찰 + 왜 문제인지(시청자 관점) + 내 맥락 + 원하는 결과 + "원인 규칙을 찾아 제안/수정하고 그 구간만 다시 구현"`. 06 문서에 당신 프로젝트용으로 채워 두었다.
2. 파일 덮어쓰기: 당신 build_video.py는 항상 `final.mp4`, `compositions/scene-XX.html`로 덮어쓴다. `episodes/<ep>/longform/renders/final_v003.mp4`처럼 **빌드 번호를 붙이는 한 줄**을 넣어라(05 문서에 패치 제안).

### 2-7. [50:30–65:30] 이미지 배치 — 일러스트 스타일에 직결

- `[51:02]` 이미지에 줌인을 넣는 이유: "몰입되게, 이탈하지 않게".
- `[51:40]` **"코드로 선을 다 그리다 보니 깨지시는 분들도 많았다 … 간단한 아이콘은 잘 그리는데 어려운 선들은 오류가 많이 생긴다 … 그래서 보통 이미지를 만들어서 넣어요."** `[52:29]` 혼잡스도 이미지. `[53:13]` GPT 이미지 생성은 "만능", 클로드는 이미지 생성이 없다.
- `[55:12]` 곰 이미지 48장 폴더: "이게 정리되어 있는 건가요? 아니다. AI 입장에서는 다 곰 이미지 … '30-B는 공허하게 허공을 바라보고 있어서 어떤 분위기에 쓰면 좋겠다'까지 있어야 정리된 것." 사람이 다 적을 수 없으니 AI에게 분석시킨다.
- `[56:33]` 곰 다큐 실습 프롬프트(강사가 현장에서 수정한 최종형):
  0. 목적: "단조롭지 않게 모든 감각을 살려서 진짜 다큐멘터리처럼"(현장에서 추가)
  1. **이미지 분석**: 전부 읽지 말고 어떤 장면들이 있는지 분류. 와이드/클로즈업/디테일. 자막 자리를 위해 어느 쪽이 비었는지(빼도 됨).
  2. 대본 분석: 문장 단위로 끊고 음성에서 몇 초에 나오는지.
  3. 배치: 문장마다 어울리는 이미지, 왜 골랐고 왜 나머지를 버렸는지 근거. (강사는 "8장 안쪽" 제한을 뺐다 `[61:40]`)
  4. 움직임: "정지면 죽은 화면 … 아주 미세하게만, 천천히 확대되거나 흘러가는 정도. 눈에 띄면 실패인데 단조로워도 안 돼, 반복돼도 안 돼."

**적용 (일러스트 스타일의 핵심 설계 결정):** 강사 말대로 **복잡한 일러스트를 코드(SVG path)로 그리게 하면 깨진다.** 그래서 선택지는 둘이다.

| 방식 | 장점 | 단점 | 권장 |
|---|---|---|---|
| A. 생성 이미지(나노바나나/GPT)로 장면별 일러스트를 만들어 PNG로 배치 | 레퍼런스 질감 재현이 쉽다 | 장면마다 스타일 흔들림, 인물 일관성, 비용, 텍스트 오타 | 캐릭터·소품 **부품**을 한 번 만들어 재사용할 때만 |
| B. 단순한 SVG 부품(굵은 라인 아이콘, 색 블록, 종이 질감)을 코드로 조립 + 드로잉 애니메이션 | 일관성, 수정 용이, 모션 가능 | 15장 레퍼런스 수준의 "그림"은 못 그린다 | **본체** |

권장 조합: **B가 본체, A는 "캐릭터 1명 + 손 + 커피잔 + 노트북 + 서류 + 달력" 같은 고정 부품 세트(투명 PNG)**를 만들어 assets/illustrations/에 넣고 목록 파일(무엇, 어느 대사에, 여백 위치, 비율)을 적는다 — 곰 48장 분류법 그대로. 이렇게 하면 DAY1 "디자인 소스는 있어야 한다"와 DAY2 "코드로 그리면 깨진다"를 동시에 만족한다.

### 2-8. [65:30–75:00] 레퍼런스 탐색 실패, 로고·음악, 이미지 확보 비용

- `[65:31]` 질문 "레퍼런스는 어떤 방식으로 찾나요?" → 강사의 실패담: 인스타툰 레퍼런스를 찾게 했더니 로그인 벽 때문에 **네이버 이모티콘을 가져와 레퍼런스라고 제시**, 시간이 배로 걸렸다. 해법: 목적을 다 입력하고 자유도를 주거나, "최소 100개" 같은 숫자를 주고 "잘 찾은 방법으로 100개 더".
- `[69:27]` 로고 폴더: 파일명만 잘 붙여도 "카카오톡"이라고 하면 로고를 가져다 쓴다. `[70:15]` 음악: "감성적인 클로징에 쓰는 음악", "흥미로운 도입" 식으로 사람이 용도를 적어야. `[71:40]` "효과음이나 음악 분류는 아직 성공 못 했다. 파형만 읽어서."
- `[72:47]` 이미지가 없을 때: 1) 리서치(짤 플랫폼, 토큰 많이 듦) 2) API로 빌려오기(나노바나나 "한 장 55원 … 100장이면 550원") 3) ChatGPT 구독으로 직접 뽑아 클로드에 분석시키기. `[74:49]` 코덱스 구독 29,000원 vs 영상 하나에 1,000원 내외 API.
- `[76:22]` 수강생 결과물에서 "라인이 좀 깨져 있어 … 어려운 건 억지로 라인으로 그리려다 오류".

**보완:** 55원×100장은 5,500원이다(자막상 "550원"은 계산 착오). 단가 자체도 촬영 시점 값이라 재확인 필요. 당신의 경우 부품 세트가 20~40장이면 총액이 수천 원 수준이라 어느 쪽이든 비용은 쟁점이 아니다. 쟁점은 **일관성**이다.

## 3. DAY2에서 "그대로 따르지 말 것"

1. 금지 규칙을 아예 없애라는 뜻으로 받아들이면 안 된다. 원본 보존, 개인정보, 화면 밖 텍스트 금지, 가짜 UI 금지 같은 **제약은 명시**한다(강사도 DAY3에서 인정).
2. "레퍼런스 100개"는 숫자를 채우는 게 아니라 좋은 것 5개를 사람이 먼저 고르는 편이 빠르다.
3. 비용 계산은 직접 다시 한다(55원×100 = 5,500원).
4. "AI가 '평면으로 잘못 일반화했다'고 말했다"는 사후 설명일 수 있다. 실제 규칙 파일의 어느 줄인지 보여 달라고 해야 한다.
